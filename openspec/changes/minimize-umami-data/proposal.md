# Proposal

## Why

Umamiの自動計測は閲覧URLと参照元のパスを取得し、パスに含まれるDIDやレコードキーと本文由来のページタイトルも送信し得る。入口、遷移、滞在の分析をルート単位で続けながら、日英の公開プライバシー記述に沿って送信データを減らす。

## What Changes

- ページの種類をSvelteKitのルートIDで送る。ニュース記事など同じルートの個別ページは一つの分類に集約する。
- 参照元は、アプリ内の遷移では直前のルートID、外部流入ではHTTP(S)の参照元オリジンに絞る。ページタイトルは送信項目から外す。
- OAuth診断の固定項目に同じ最小化済みのページ情報を添える。Do Not Trackの条件を維持する。
- 日英の公開プライバシー記述を実際の送信範囲に合わせる。

## Impact

ルートレイアウトのナビゲーション通知、Umamiクライアント、公開プライバシーのUmami欄を変更する。既存画面の表示・ルーティング・OAuth処理・Vercel Web Analytics・配備設定は対象外。読み込み条件の修正を含むPR #252と並行して検討し、併合時は双方の条件を維持する。
