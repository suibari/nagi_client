# Design

## Context

Vercelの `/thread/:did/:rkey` は共有メタデータ付きのSPAシェルを返す。クライアントは `/thread/[did]/[rkey]` で既存のAppView APIから投稿と返信を取得する。ニュース・ブログの個別ページでは、未ログイン時に `GuestHero` から `/login` へ案内する。ブログでは記事とコメントの後ろに紹介がある。

## Goals / Non-Goals

公開投稿詳細を訪れた未ログインの閲覧者が、会話を読んだ後に同じ紹介から参加できるようにする。認証遷移、公開範囲の判定、計測は既存の処理または別の変更の責務とする。

## Decisions

- 投稿詳細の会話表示に続けて既存の `GuestHero` を描画する。ブログと同じ順序にすることで、共有された会話から読み始められる。
- 投稿取得に成功し、ルートにこっそり・削除・利用不可の状態がなく、OAuthの確認を終えてセッションがない場合に表示する。投稿詳細は初回の投稿取得もブラウザで行うため、静的HTMLに紹介を含めず、認証復元完了を待てる。
- 参加とNagi紹介のリンク、およびアカウント作成の手順は共通部品と既存の認証画面を利用する。

## Risks / Trade-offs

AppViewの応答が失敗した場合は既存のエラー表示になる。投稿の取得条件は既存のAppViewの契約に従い、テストはクライアントが受け取る応答を再現して行う。
