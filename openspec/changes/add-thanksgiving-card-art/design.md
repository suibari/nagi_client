# Design

## Context

AppView の記念日カード定義には `thanksgiving_us`（スロット 14）がある。祝日の定義は11月の第4木曜日。記念日カードの判定は祝日定義の地域情報を参照せず、日本時間午前4時を境にしたカード日付を用いる。本人の未受領分は同じ記念日カードの受け取り経路で配られる。

AppView は当日の受け取り候補と所持カードの表示情報を共通のカード定義から組み立てる。現時点でサンクスギビングデーの定義に `art` がなく、クライアントは背景画像を読み込まない。

## Goals / Non-Goals

受け取り時と所持後で共通のカード面を使い、今回のイラストをライト・ダーク両テーマで読めるようにする。取得条件、所持データ、公開範囲は現行契約に従う。

## Decisions

- AppView の `anniversary_cards.json` で `thanksgiving_us` の `art` に `anniv-thanksgiving-us` を指定する。API の画像指定を利用することで、受け取り時の先読みと表示が同じファイルを指す。所持済みカードの表示でも年ごとに同じ定義を引くため、過去分にもイラストが反映される。
- Web クライアントの `static/card-art/` から可逆 WebP を配信する。原画の透過線画を既存のテーマ処理の対象に加える。色調整は既存の CSS に任せる。
- 記念日や年を特定するための新しいデータは不要。既存の番号と所持レコードからカード定義を引ける。

## Risks / Trade-offs

- AppView が先に画像名を返すと、クライアントに画像が届くまで背景が表示されない。WebP を先に公開し、画像 URL の HTTP 応答を確認してから AppView の定義を反映する。
- 原画は156 × 220 px。カード表示時の拡大やトリミングは既存カード面の描画に従うため、開発用のカード表示で文字との重なりと両テーマの見え方を確かめる。

## Migration Plan

クライアント、AppView の順に反映する。差し戻しが必要な場合は AppView の画像指定を戻すと、従来のカード面に戻る。取得済みのカードは既存の番号で引き続き参照できる。
