# Design

## Context

動機は [proposal.md](proposal.md) のWhyを参照する。

- ドローAPIはダイアログを開く前に呼ばれ、結果（カード・レア度・isNew）は開封前に確定している。
- 取得演出はすべて `CardDetailDialog` が `draw` の有無と `alreadyDrawn` で駆動している。通常（/cardsの帯・図鑑）・ゲスト・記念日の各経路は、このダイアログに `draw` を渡すだけである。リアクションでの抽選は廃止済み。
- 記念日カードはルートレイアウトの `AnniversaryCardHost` が受け取り待ちを見つけると自動で受け取り、どのページでもダイアログを開く。`draw.source` は `anniversary`。
- 素材：`static/bot_image_hero_trans.webp`（600×900、透過、約200KB）、`static/zenkatsu-logo.png`（1671×941、約1.1MB）。
- レア度別の時間・色・振動は `src/lib/cards/celebration.ts` の `CARD_REVEAL_EFFECTS` に集約されている（cards-zenkatsu D2）。
- `CardBack` は「押す前に見えているもの」と「めくれるもの」を同じ絵にする前提で、帯・FABとフリップ演出で共用している。

## Goals / Non-Goals

**Goals:**

- 利用者が自分の操作でパックを開け、カードを取り出す感触を作る。
- 既存のレア度演出・祝いの発火条件（CARD-04）を変えずに前段へパックを足す。

**Non-Goals:**

- レア度の演出時間や振動の再調整。
- 複数枚のパックや、パックの種類による演出差。

## Decisions

### D1: パックは `CardDetailDialog` の演出段階として足す

**課題**：抽選の経路は複数あり、それぞれに開封を実装すると挙動がずれる。

**採用判断**：`CardDetailDialog` の段階を「パック → 取り出し → タメ（既存） → 表」とする。パックを出す条件は既存の `shouldAnimate`（`draw` があり `alreadyDrawn` でない）に、`draw.source !== 'anniversary'` を加えたものにする。

**理由と制約**：閲覧や再取得でパックを出さないことが、既存の演出条件からそのまま従う。記念日カードは利用者が引く操作をせずページ表示時に自動で開くため、そこへ開封操作を求めるとわずらわしい。現行どおりタメ→表で見せる。タメのタイマーと振動はパックが開いた時点で始める（現状はダイアログを開いた時点）。

### D2: なぞる操作は進み具合に追従させ、タップでも開ける

**課題**：なぞって破る操作は手応えが強いが、指が不自由な場合やマウス・キーボードでは難しい。

**採用判断**：Pointer Eventsで切り取り線に沿った横移動量を追い、破れ目をその分だけ進める。線の幅の約6割を越えて離したら残りを自動で破る。届かずに離したら少し戻る。タップ（移動がほぼ無いクリック）とEnter／Spaceは、破れるアニメーションを自動で再生する。

**理由と制約**：縦スクロールとの競合を避けるため、パック上では `touch-action: none` にする。ダイアログ内はもともとスクロール不要な大きさなので影響は小さい。破れ目の表現はCSSのclip-pathで封の部分を切り分け、画像素材は増やさない。

### D3: パックからはレア度を漏らさない

**課題**：パックの段階でレア度が分かると、開ける前に結果を知ってしまう。

**採用判断**：パックの見た目・振動は全レア度で同じにする。昇格色などはカードが出てからにする。

**理由と制約**：既存の `CARD_REVEAL_EFFECTS` をそのまま使えるため、演出の調整箇所が分散しない。

### D4: パックの絵はゼンカツのロゴとbotたん、地は裏面と揃える

**課題**：パックは開ける前の期待を作る面で、Nagiのカードであることがひと目で分かる絵が要る。一方、出てくるカードと地の色がばらばらだと取り出したものがつながらない。

**採用判断**：地はブランドのグラデーションで `CardBack` と同じ配色にする。上部にゼンカツのロゴ、下部にbotたん（`bot_image_hero_trans`）を置き、botたんはパックの下端で切れる構図にする。上端に切り取り線とギザギザの封を置き、開いた口から `CardBack` がせり上がる。

**理由と制約**：ロゴの原本は約1.1MBあり、ドローのたびに読むには重い。パックの表示幅に合わせて縮小したwebpを別に用意し、/cardsの表示時に先読みする。画像の読み込みが間に合わない、または失敗した場合も、地と切り取り線だけで開封できるようにする。画像は装飾なので `alt=""` とし、パックのアクセシブルネームは開封の案内文で付ける。

### D5: 開封前は背景クリックで閉じない

**課題**：なぞる操作がパックの外まで流れて指を離すと、背景クリックとして扱われてダイアログが閉じうる。

**採用判断**：パックの段階では背景クリックを無視する。Escキーとスキップボタンは使える。

**理由と制約**：カードはAppViewで確定済みなので、開封前に閉じても所持は変わらない。閉じた場合の扱いは今と同じく `onclose` でコレクションへ反映する。

### D6: 動きを減らす設定ではパックを出さない

**課題**：破れる・せり上がる動きは prefers-reduced-motion の利用者には負担になる。

**採用判断**：今と同じく最初から表を見せる。パックの操作も挟まない。

## Risks / Trade-offs

- 取得までの操作が1回増える → スキップを最初から出し、タップでも開けるようにする。
- 古い端末でclip-pathのアニメーションが重い → 破れ目の更新は `transform` と1要素のclip-pathに限る。
