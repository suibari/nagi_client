# Design

## Context

動機は [proposal.md](proposal.md) のWhyを参照する。

- 通常のComposerでは、本人のクロスポスト済み投稿のコピーを参照できる場合だけ、引用付きの投稿をBlueskyへ出せる（`ownCrosspost()`と`checkCrosspostTarget()`）。Bluesky側では`app.bsky.embed.record`、メディアがあれば`recordWithMedia`になる。
- ニュースの引用は共通Composer（`openQuoteNews`）から投稿し、引用先にコピーが無いためクロスポストを選べない。専用の`NewsQuote`クラスは使われていなかった。
- `QuotePick.handlePaste`は、Nagiのスレッド URL を単独で貼ると貼り付けを止めてから引用先を判定する。引用できない相手と分かっても本文へURLを戻さない。
- 本文中のURLは`parsePostText().cardUrls`を通じて自動でリンクカードになる。Nagiのスレッド URL も例外ではなく、他人の投稿のURLを文中に書くと、その本文が入ったOGPのカードが付く。
- `/thread/{did}/{rkey}`と`/news/{rkey}`のOGPは、こっそり・既定でぼかすラベルの境界を守る（SEO-03）。

## Goals / Non-Goals

**Goals:**

- Nagi投稿・ニュース・ラジオを引用した投稿を、引用が消えない形でBlueskyへ出せるようにする。
- 他人のNagi投稿の本文を、引用でもカードでも自分の投稿の中に見せない。
- 他人のNagi投稿のURLを、リンクとしては貼れるようにする。

**Non-Goals:**

- 返信と引用の同時外部化。
- 引用できる相手の拡大。
- Bluesky上でのNagiリンクの見た目の独自化。カードはOGPのとおりに出す。

## Decisions

### D1: クロスポストでの引用は、コピーの引用 → リンクカードの順に決める

引用先が本人のクロスポスト済み投稿でコピーを参照できるなら、従来どおりコピーを引用する。Bluesky上で会話としてつながるからである。それ以外は、引用先の公開URLをリンクカードにする。

| 引用先                                   | Bluesky側                      |
| ---------------------------------------- | ------------------------------ |
| 本人のクロスポスト済み投稿（コピーあり） | コピーの引用（従来どおり）     |
| 本人の投稿（コピー無し）・botたんの投稿  | `/thread/{did}/{rkey}`のカード |
| ニュース                                 | `/news/{rkey}`のカード         |
| ラジオ                                   | 曲ページのカード               |
| 本人のこっそり投稿                       | クロスポストできない           |

検討した代替案：

- **貼った後に「引用／リンク」を利用者が選ぶ**：自由度は上がるが、毎回判断が増える。Blueskyで紹介したいだけなら、この選択は要らない。
- **URLの自動引用をやめ、カードから引用へ変える操作にする（POST-07の見直し）**：URLを貼って引用する今の使い方を壊すので、今回の問題に対しては大きすぎる。
- **ニュースのリンク先を元記事にする**：Blueskyの読者には自然だが、Nagiへの誘導とサインアップの動線にならない。利用者判断（2026-11-22）でNagiのニュースページにした。

### D2: メディアと重なったら、URLを本文の末尾へ入れる

Blueskyの`recordWithMedia`はレコードとメディアを同時に持てるが、externalとメディアは同時に持てない。画像・動画があるときはメディアを埋め込み、引用先のURLを本文の末尾に空行で区切って足す。分割（BSKY-05）の前に足すので、URLのfacetは分割で切れない。Nagiの本文にあるリンクカードより、引用のカードを優先する。

### D3: 他人のNagi投稿のURLは、どの経路でもカードにしない

引用を本人とbotたんに限っているのは、相手の本文を自分の投稿の中に見せないためである。OGPのカード画像にも本文が入るので、カードにすれば実質的に引用になる。そこで、単独で貼った場合も文中に書いた場合も、他人の投稿のURLはリンクの文字だけにする。

URLのDIDが本人なら本人の投稿と分かる。botたんの投稿かどうかは、AppViewが付ける`isBot`でしか分からない。本人以外のスレッド URL は投稿を取得して判定し、判定できるまではカードを付けない。

### D4: 他人の投稿を単独で貼ったら、URLを本文へ戻す

引用できないと分かったら、取り込みを止めた位置にURLを文字として入れる。エラーの表示は出さない。引用先が見つからない場合（削除済み等）は、従来どおりURLを戻さず理由を出す。

## Risks / Trade-offs

- **コピーが消えている自分の投稿**：従来は送信を止めていた。今後は引用をリンクカードに切り替えて投稿できる。返信の場合は孤立した返信になるので、従来どおり止める。
- **OGPの取得失敗**：カードのメタデータが取れなくても、MEDIA-06と同じくホスト名で投稿を塞がない。
- **リンクを開いた先が見られない**：ログインが要る、ラベルで伏せられるなど、Bluesky側の読者が開いた先で本文を読めない場合がある。OGPの境界（SEO-03）に任せる。

## 確認済みの細部

2026-11-22に利用者が推奨どおりで合意した。

1. ブログ（BLOG-07）でも、他人のNagi投稿のURLはカードにしない。記事はstandard.siteにも出るので、通常投稿より慎重に扱う。リンクカードの判定は入力欄の種類によらず共通にする（Bluesky専用の入力欄も含む）。
2. 他人の投稿のURLを単独で貼ってリンクとして残したとき、案内は出さない（D4）。
