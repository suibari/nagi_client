# Design

## Context

投稿範囲モーダルではNagiとBlueskyの返信範囲を別々に選ぶ。Bluesky側のコントロールは同モーダル、Bluesky専用投稿、投稿後の設定で共有している。Nagiでは投稿者本人が引き続き返信できる。背景は[返信範囲導入時の設計](../2026-11-25-add-nagi-reply-gate/design.md)と[投稿の設計 D10](../../../specs/post-composer/design.md)を参照。

## Decisions

日英の辞書で「返信できる人」「誰でも」「返信不可」に対応するキーを共有する。選択値のマッピングは各コントロールに残し、NagiとBlueskyはそれぞれの設定として保存する。共通ラベルを別々のキーに持つと翻訳更新で再びずれる。画面にはサービス別の見出しを残し、設定の対象を示す。

## Risks / Trade-offs

「誰も返信できない」は、Nagiでは投稿者本人も返信できないと読める。既存の「返信不可」を使い、投稿後に変更できるかどうかは各サービスの仕様に従う。翻訳キーの整理によるデータ移行は不要。

## 周辺文言の確認

| 画面・操作 | 確認結果 |
| --- | --- |
| 返信できない投稿 | Nagiの「この投稿には返信できません」に対し、Blueskyでは末尾に「。」が付く。投稿カードのツールチップでは句点の差があり、Blueskyの送信エラーにも同じ文言が使われる。 |
| 作者のミュート | Nagiのプロフィールでは「ミュートする」「ミュート解除」。Blueskyの投稿メニューでは「@ハンドルをミュート」「@ハンドルのミュートを解除」。投稿から操作する場合は対象のハンドルが分かる。 |
| ブックマーク | 「ブックマーク」「ブックマークを解除」は一致する。保存先やフォルダの有無に応じて案内が異なる。 |
| 通報 | Nagiは「運営に伝える」、Blueskyは「Blueskyに通報」。送信先と理由の選択肢が異なる。 |
| 投稿の削除と送信 | 「Blueskyの投稿を削除」「Blueskyへ投稿」は削除対象や投稿先を明示する。 |
| クロスポストの案内 | 設定・ログインでは「同時投稿」、紹介・ブログ・失敗通知では「クロスポスト」が使われる。設定の返信対象と長文の案内は現行仕様との差もある。[既知の不整合](../../../known-gaps.md#bluesky連携設定の案内)を参照。 |
