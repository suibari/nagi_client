# Design

## Context

動機は [proposal.md](proposal.md) を参照。`feedGestures` はbuttonを一律除外し、`ImageGallery` の画像タイルはbuttonで実装されている。NagiとBluesky、引用、記事内画像、3行日記が同じ画像部品を利用する。既存FEED-08はメディア除外を定めており、本件は現行仕様への不具合修正ではなく除外範囲の変更として扱う。

## Goals / Non-Goals

**Goals:** 画像タイルを明示的に識別し、共通認識器で横ドラッグとタップを区別する。キーボードによるbutton操作を保つ。

**Non-Goals:** button全体の除外解除、拡大ビューのジェスチャ追加、個別フィードごとの認識器の複製。

## Decisions

### 画像タイルに限定して除外の例外を認める

`ImageGallery` の拡大用buttonに専用data属性を付け、`gestures.ts` はそのbuttonだけを許可する。明示的な無視指定・動画・入力・通常リンクなどの祖先と、既存の内部スクロール判定を優先する。単にimgを含むbuttonをすべて許可すると、アイコン付き操作や警告解除まで対象になるため採らない。警告解除と再非表示は例外に含めない。portalでbody直下へ出る拡大ビューはタブ認識器の外に保つ。

### 横ドラッグ後だけクリックを抑止する

認識器が画像起点の横ドラッグを確定したら、その操作に続くクリックをcapture段階で抑止する。タブ移動が成立しない短いドラッグや中断でも同じ扱いとする。通常タップ、キーボードによる起動、次の独立した操作は妨げない。抑止状態は次の独立した入力とdestroyで解除し、タブ切替後へ漏らさない。全クリックを常時禁止する案はアクセシビリティと画像閲覧を損なうため採らない。

## Risks / Trade-offs

- ドラッグ後にクリックが合成され画像を開く可能性 → 移動成功・戻り・中断の各経路と、次のタップを操作テストで確認する。
- 通常の操作部品へ例外が広がる可能性 → 明示属性の付いた拡大buttonだけに限定し、警告操作・通常リンク・内部スクロールの除外を検証する。
- ブラウザ間でタッチ後のクリック挙動が異なる可能性 → Chromiumの実タッチ入力を使う既存E2Eで検証し、実機で未確認の範囲は検証記録に残す。

## Migration Plan

データ移行や外部APIの変更はない。実装後に主仕様・設計・known-gapsを同期する。保存データ・個人情報・公開範囲・外部書き込みに変更はない。取り消す場合は画像タイルの例外とクリック抑止を戻す。

既存判断の出典は [feed-thread/design.md](../../../specs/feed-thread/design.md) と [導入時固定履歴](../../../reference/comment-snapshot/feed-thread.md) を参照し、固定原文は更新しない。過去の除外理由についてコードから確認できない経緯は推測しない。

## 機能概要

画像タイルからも隣のタブへ移れるようにし、タップによる画像閲覧と両立する。

| 機能               | 役割                             | 要件    |
| ------------------ | -------------------------------- | ------- |
| 画像上の横スワイプ | 本文と同じタブ移動を行う         | FEED-08 |
| タップとの区別     | ドラッグ後の意図しない拡大を防ぐ | FEED-08 |

主な利用の流れ：画像に触れる → 横へ動かす → 隣タブを確認して指を離す。タップだけなら画像を拡大する。
