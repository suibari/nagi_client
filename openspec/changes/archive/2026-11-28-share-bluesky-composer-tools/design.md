# Design

## Context

`PostModal` はNagiとBlueskyで `PostModalShell` を共有する。Bluesky用の `BskyComposer` も `ComposerEditor`、画像選択・編集、リンクカード編集を使う。現行の `emojiPickerEnabled={false}` は絵文字とタグの両ボタンを隠す一方、本文内のカスタム絵文字サジェストには伝わらない。送信処理はNagi独自の絵文字facetを取り除くが、Bluemojiのfacetは保持する。Blueskyの各クライアントでの描画は確認していない。 [提案](proposal.md)

現在の返信成功処理はモーダルを閉じてBlueskyへのリンクを通知する。会話カードは送信結果を購読しておらず、フィードの更新でスレッドを取得する。ルートの返信数が0で既存返信を持たない場合は取得を省くため、タブの即時再取得を足すだけでは古い返信数や取得結果に左右される。 [既知の不整合](../../../known-gaps.md)

## Goals / Non-Goals

本文の操作と返信・引用先カードの表示構造を共有する。送信処理と下書きのライフサイクルは現在のNagi用とBluesky用の各コンポーネントが担う。Bluesky用の公開先表示、破棄確認、返信・引用制限の操作は `BskyComposer` の責務とする。

## Decisions

### 利用の流れ

Bluesky投稿から返信または引用を開き、画像ボタンと同じツールバーでタグか絵文字を選ぶ。本文で挿入位置を確認して送信すると、投稿が完了したタグは次の投稿で選べる。

| 機能 | 要件 |
| --- | --- |
| Blueskyへの入力と投稿、返信の即時表示 | BSKY-09 |
| Unicode絵文字の検索と挿入 | EMOJI-01、EMOJI-02 |
| タグパレットと投稿後の履歴 | TAG-01、TAG-02 |

### パレットと入力中の候補に同じ制約を渡す

`ComposerEditor` でタグの表示可否と絵文字の種類を独立して指定できるようにする。Nagiの通常投稿での既定値とゲスト投稿の既存ボタン表示は維持する。Bluesky用はタグを表示し、Unicode限定の設定を `QuickEmojiPalette`、その全件表示の `EmojiPicker`、`ComposerInput` に伝える。単純に現行フラグをオンにすると、パレット・検索からもカスタム絵文字が選べるため、設定で候補範囲を明示する。

Unicode限定の一覧は、保存済みのお気に入りや履歴から表示用の候補を導出する。並べ替え・追加・削除では、元の保存配列に対して選んだ項目を操作する。Unicode検索には既存の日本語・英語の索引を使う。カスタム候補の取得を避けるため、Unicode限定の経路からカスタム絵文字の検索・解決を呼ばない。

### 実際の送信本文をタグ履歴へ反映する

既存の `insertTag()` とfacet生成・分割を使う。送信済みの各分割単位のfacetを投稿順で既存の履歴処理に渡す。入力段階の本文から集計すると、分割時に境界をまたいで落ちたfacetまで履歴に入る。送信開始時のアカウントを確認して履歴を更新し、処理中に切り替えたアカウントの履歴へ混入させない。gate設定に失敗しても全投稿を作成済みであれば履歴を更新する。送信に使うAPI・スコープには追加がない。

### 返信・引用先のカードは表示だけを共有する

カードの枠、返信・引用の表示、著者の配置を共通部品に置く。本文・ニュース・ラジオの内容、Nagiのモデレーション、引用解除ボタンは呼び出し元から渡す。親コンポーネントを統合すると公開範囲や保存の状態も混ざるため、共通部品には投稿先の決定や書き込みを持たせない。

### PDSで作成を確認した返信を会話へ差し込む

`postToBluesky` の送信経路から、PDSで作成が確認できた返信のURI・CIDと、実際に書き込んだレコードの内容を得る。返信のルートURIと送信時のセッションにひも付けたメモリ上の表示データを、モーダルを閉じる前に登録する。分割の途中で失敗した場合は、既存の途中失敗の案内とともに作成済みの分を渡す。同じ会話をリポスト等でも表示している場合はルートURIで同じ結果を参照する。

`BskyThreadUnit` でサーバーの会話と一時的な返信をURI単位で突き合わせ、既存のプレビュー、インデント、モデレーションを通す。投稿が確認できたルートのスレッドキャッシュだけを無効化し、表示中の会話を再取得する。通常の更新も引き続き使う。古い応答が返信を含まない間は表示を保持し、同じURIの確定データを受け取ったらそちらを使う。利用不可が明示された場合や本人が削除した場合は、表示データも取り除く。セッション変更時に表示データを破棄し、変更前の遅い応答を適用しない。

Blueskyへの引用は独立したルートになる。今回の差し込み対象は返信先の会話で、引用後は既存の投稿完了通知を使う。 [Nagiの投稿追従の設計](../../../specs/feed-thread/design.md#d2-投稿への追従は確定後も続ける)

## Risks / Trade-offs

- パレットのお気に入りを絞り込んだまま保存すると、カスタム絵文字が消える。Unicodeのみの一覧で編集した後、Nagi側でカスタム絵文字の内容と順序を確認する。
- 先行する日本語・絵文字で文字位置とバイト位置がずれる。分割後を含む投稿レコードのfacetが対象タグを指すことを検証する。
- カードの共通化で引用の解除やモデレーション表示を落としやすい。Nagiの本文・ニュース・ラジオの各カードとBlueskyの返信・引用を既存の操作経路から確認する。

- 返信の作成と会話取得の順序が前後する。返信数0からの投稿、作成直前に始まった取得、取り込みの遅延、確定後の重複をモックで再現する。
