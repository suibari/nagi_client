# Design

## Context

動機は [proposal.md](proposal.md) のWhyを参照する。

- getChronicleは1ページ＝1年を古い順に返し、`cursor` は次に返す年である。今の年表は最初の年だけを読み、InfiniteScrollで末尾に近づくたびに次の年を読む。
- 既読は年単位で、ページを読み込んだ時点で `markChronicleSeen` が既読にする（CHRON-02）。未読判定（notice.ts）は別途、全年を順に取得している。
- 年表は日記ページのタブ内にあり、スクロールするのはウィンドウ全体である。紹介ページでは `preview` で短いサンプルを描く。
- `base.css` は `prefers-reduced-motion: reduce` のとき全要素へ `animation: none !important` を当てる。演出の基底状態が読めない状態だと、演出を切った人には読めなくなる（既存のD4・テストで担保している制約）。

## Goals / Non-Goals

**Goals:**

- 開いた瞬間に今の節目が見え、過去のどの年へも1操作で移れる。
- 年の切り替わりが画面の主役として目に入り、眺めて楽しい。
- 演出を切っても、非対応ブラウザでも、内容と読みやすさは同じに保つ。

**Non-Goals:**

- 並び順を新しい順へ変えること。「はじまりから今へ」読むものという性格を保ち、初期位置だけを今にする。
- 月単位の目盛り、年表内検索。

## Decisions

### D1: 全年を先に読み、末尾から始める

年表を開いたら、`hasMore` が偽になるまで古い年から順に読み込み、終わったら末尾の節目へ瞬時にスクロールする。スクラバーの目盛りは年表全体の高さを前提にするため、全体が揃ってからでないと位置が決まらない。Nagiの利用期間は数年で、ページ数は年数と等しいので、数リクエストで済む。cursorが繰り返したら打ち切る（notice.tsと同じ防御）。

検討した代替案：最新の年だけを先に読み、スクラバーで選んだ年を直接読む。AppViewはcursorとして起点の年から今年までの任意の4桁の年を受け付ける（lexiconにも「次に返す年」と記載、2026-11-12確認）ので、技術的には可能である。ただし年の範囲を知るために起点の年と今年の2ページを先に読む必要があり、未読み込みの年は高さが分からないため目盛りを推測で置いて読み込むたびに補正することになる。読み込むたびに上へ内容が差し込まれるのでスクロール位置の補正も要り、年末年始の4時前後はクライアントとサーバで「今年」がずれて400になりうる。数年分なら全年読み込みのほうが単純で目盛りも正確なため、利用者の判断で全年読み込みとした。

既読は「読み込めた年」のままにする。開くだけで全年が既読になるが、利用者の判断で受け入れた（CHRON-02の追加シナリオ）。

### D2: スクラバーは右端の縦レール、栞のつまみ

レールは年表の表示範囲の右端に `position: fixed` で置き、上端はアプリのヘッダー下、下端はナビゲーションと投稿ボタンを避ける。各年の目盛りは、年見出しの年表内オフセットを年表全体の高さで割った比率で配置し、`ResizeObserver` で年表の高さが変わるたびに測り直す。つまみ位置はスクロール量から求め、`requestAnimationFrame` で間引く。

ドラッグはPointer Eventsで扱い、`setPointerCapture` で指がレールから外れても追従させる。ドラッグ中は位置を比率→スクロール量へ直接写像し、つまみの左にその位置の年を大きく出す。レールの空白をクリック・タップしたときも同じ写像で移る。キーボードとスクリーンリーダー向けには `role="slider"`、`aria-valuemin/max/now`（年）、`aria-valuetext` を持たせ、上下キーで前後の年見出し、Home/Endで最初の年・末尾へ移る。

つまみは栞の形（上端が平らで下端に切り込み）にし、最新の年の目盛りに「いま」と添える。栞は「本の今読んでいる場所」を示す印であり、年表を1冊として読ませる既存の見出し（「〜の年表」）と揃う。

### D3: 強調はscroll-driven animationだけで行う

年の数字と節目のタイトルに `animation-timeline: view()` を当て、要素が画面中央にあるときを最大、端にあるときを最小とするkeyframesを付ける。動かすのは `transform: scale()` と `opacity`（年の数字は色も）だけで、レイアウトを動かす `font-size` は動かさない。年の数字は最大の大きさで行の高さを確保し、縮めた状態から拡大する。そのため基底状態（アニメーションなし）が最大＝読める状態になり、CHRON-02の制約と両立する。

`@supports (animation-timeline: view())` の内側にだけ書き、非対応ブラウザでは基底状態の静的表示になる。JSでスクロール量を毎フレーム計算する方式は、スクラバーと二重にスクロールを監視し、低速端末でかくつくため採らない。

タイトルの拡大は `transform-origin` を行頭に置き、拡大後も幅に収まるよう要素の最大幅を拡大率で割った値にする。

### D4: 見た目の方向

- 性格は「静か・懐かしい・少し誇らしい」、世界はアルバムや手帳の背と栞。
- 画面の主役は年の大きな数字（中央に来た年がアクセント色になる）。それ以外はアプリ共通の中立色に留める。
- 見出しの太さを800から600以下へ下げ、強弱は大きさと色で付ける。
- レールは年の見出しをまたいで1本につなぎ、年見出しはレール上の大きな節として描く。
- 余白は4pxの格子に揃える。

## Risks / Trade-offs

- [年数が増えると開くたびの読み込みが増える] → 数年のうちは問題にならない。10年を超えるような規模になったら、D1の代替案（年を直接読む）をAppViewの契約とともに検討する。
- [全年読み込みで、見ていない年の未読も消える] → 利用者の判断で受け入れた。年表タブの未読印は「年表に何か新しいことがある」ことを知らせる目的で、開いた時点で役目を果たす。
- [Firefoxは現時点でscroll-driven animationが既定で無効] → 静的表示で内容は同じ。演出だけが無い。
- [固定配置のスクラバーが本文と重なる] → 本文の右側にスクラバー分の余白を取る。狭い画面でも本文が読める幅を残す。
