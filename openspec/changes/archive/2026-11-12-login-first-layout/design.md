# Design

## Context

動機は [proposal.md](proposal.md) のWhyを参照する。

- 利用者のほとんどはBluesky経由で来る（運営者の判断、2026-11-12）。
- ログイン画面の構成は、上から、大きいアイコン、見出し「Nagiに参加する」、説明文の段落、ハンドル入力、Bluesky連携のスイッチと3行の説明文、ログインボタン、「はじめての方」の節（見出し・説明文・ボタン）、年齢の告知と規約への同意、「ログインせずに見る」。
- iPhone 13相当の幅で先頭から開くと、ログインボタンが下部ナビにかかる（2026-11-12のスクリーンショットで確認）。
- `loginSignupSubmit`（「Nagiをはじめる」）はログイン画面の新規登録ボタンと、参加の締めのボタンで共用している。

## Goals / Non-Goals

**Goals:**

- 既存アカウントの利用者が、最初の画面でログインの入口を見つけられる。
- 新規登録のボタンが、アカウントを作る操作だと押す前にわかる。

**Non-Goals:**

- 新規登録を目立たなくして登録を減らすこと。両方の入口は最初の画面に置く。
- 認可や登録の流れそのものの変更。

## Decisions

### D1: ログインを主役にし、新規登録は区切り線の下に置く

**課題**：入口が2つあるが、利用者のほとんどはログインする側である。

**採用判断**：ログインを主ボタン、新規登録を副ボタンにして、同じカードに縦に並べる。最初に2択を選ばせる案と、タブで切り替える案は採らない。

**理由と制約**：2択の案は誤操作を最も防げるが、ほぼ全員の手数が1つ増える。タブの案は、タブに気づかない人が出るうえ、連携スイッチをタブごとに持つ必要がある。主・副のボタンを並べる案なら、ログインの手数は変わらず、新規登録も最初の画面に見える。誤操作は文言（D2）で防ぐ。

### D2: 新規登録ボタンとランディングの参加ボタンで文言を分ける

**課題**：同じ「Nagiをはじめる」だと、既存アカウントの利用者もこのボタンを押してしまう。

**採用判断**：ログイン画面の新規登録ボタンは「アカウントを作ってはじめる」とし、参加の締めのボタンは「Nagiをはじめる」のまま残す。文言のキーも分ける。

**理由と制約**：ランディングのボタンは、まだアカウントの有無を問わない入口なので、広い言い方が合う。ログイン画面では、アカウントを作るかどうかを選ぶ場面なので、操作の結果をそのまま書く。

### D3: Bluesky連携のスイッチは両方のボタンより上に置く

**課題**：スイッチはログインと新規登録の両方の認可に効くが、今はログイン側の部品に見える。

**採用判断**：ハンドル入力のすぐ下、両方のボタンより上に置き、説明文を1行に短くする。

**理由と制約**：認可を始める前に選ぶ必要があるので、ボタンの後ろには置けない。説明文には、同時投稿とフィード閲覧の権限であることと、あとから設定で変えられることを残す。

## Risks / Trade-offs

- 文字を大きく設定した端末や画面の小さい端末では、最初の画面に収まらないことがある → スマホ幅（iPhone 13相当とiPhone SE相当）のスクリーンショットで確認し、収まらない場合も並び順は変えない。
- 文言を変えると、外部の案内や過去の説明と食い違う → ランディングの「Nagiをはじめる」は残すので、利用者が最初に押すボタンの名前は変わらない。
