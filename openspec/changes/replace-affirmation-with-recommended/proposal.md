# Proposal

## Why

全肯定タブは「botたんがスコアを付けた投稿のうち、1人1日1件を時系列に並べる」フィードで、選ぶ基準がbotたんの採点しかない。読む人の好みは反映されず、他の人が反応した投稿も拾えない。初めて来た人や未サインインの人の最初の画面は、他人の投稿が自分と関係なく並ぶホーム（未サインインではグローバル）になっており、「ここには自分に合う投稿がある」と分かるきっかけが乏しい。

読む人の興味に近い投稿と、みんなの反応が集まった投稿を時系列に並べる「おすすめ」へ全肯定タブを置き換え、既定の一番左に置く。Blueskyから登録した新しい人は、名刺の分析と同じBlueskyの投稿・いいねから興味を推定できるので、Nagiで書く前からおすすめが働く。

## What Changes

- 全肯定タブを廃止し、おすすめタブに置き換える。保存済みの全肯定タブは同じ位置でおすすめタブになる。`/affirmation` と `?tab=affirmation` の旧リンクはおすすめを開く。
- 既定のタブを「おすすめ / ホーム / グローバル」に変える。未サインイン・新規・タブを保存していない人は一番左がおすすめになる。保存したタブの並びは変えない。
- おすすめの候補は「閲覧者の興味に近い投稿」または「リアクションが集まった投稿」とし、時系列（新しい順）に並べる。botたんのスコアは候補条件にしない。
- 同じ人の投稿は1人1日1件までにする（多様性）。その日の候補が複数あれば、興味に近い投稿を優先し、無ければ反応の多い投稿を出す。
- 興味が分からない人（未サインイン、材料が足りない人）には、リアクションが集まった投稿だけを出す。
- 興味の材料は、Nagiの投稿が十分にあればNagiの投稿、なければ新規登録時に集めるBlueskyの投稿・いいね（名刺の分析と同じ材料）とする。
- 件数（リアクション数など）は画面に出さない。並びの判定にだけ使う。
- AppViewにおすすめを返すAPIと、Bluesky由来の興味の保存を追加する。旧クライアント向けに全肯定のAPIはしばらく残す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `feed-thread`: FEED-01の既定タブと旧リンクの扱いを変更し、おすすめタブの要件（FEED-10）を追加する。
- `appview-protocol`: おすすめの取得契約と、興味の材料・保存に関する契約（API-10・API-11）を追加する。

## 確認したい点（合意済みの方針以外）

1. **「リアクションが集まった」の基準**：推奨は「投稿者本人とbotたんを除く5人以上がリアクションした投稿」。母数が小さいため、件数を大きくすると候補が尽きる。
2. **botたんの投稿**：推奨はおすすめから除く。botたんの日記や気まぐれ投稿は毎日反応が集まるため、1人1日1件でも毎日先頭近くに並び続ける。グローバルでは今までどおり読める。
3. **Blueskyの投稿の埋め込みを保存すること**：興味の近さを測るため、新規登録時に読んだBluesky投稿のうち最大10件の埋め込みベクトルをAppViewに保存する（本文は保存しない）。Nagiの投稿が5件たまったら、Nagiの投稿で測るよう切り替え、Bluesky由来のベクトルは削除する。名刺の分析と同じく、公開されている投稿だけを材料にする。

## Impact

- クライアント：タブの型・既定・正規化（`src/lib/feed-tabs/`）、タブの取得解決（`resolve.ts`）、`/affirmation` 互換ルート、タブ追加ダイアログ、i18n（タブ名・空表示）、未読位置のキー。
- AppView（別リポジトリ）：おすすめAPI（`com.suibari.nagi.getRecommended`）、`parseFeedTabs` の `source: 'recommended'` 受け入れと `affirmation` からの読み替え、興味ベクトルの保存と取得。
- bot（別リポジトリ）：新規登録時の分析ジョブ（`source: 'bluesky'`）で、Bluesky投稿の埋め込みを興味ベクトルとして保存する。
- lexicon（別リポジトリ）：`getRecommended` の定義、タブの `source` に `recommended` を追加。
- 仕様書：`feed-thread` のspec/design、`appview-protocol` のspec/design。
- 非対象：おすすめの理由の表示、興味の手動編集、Blueskyの投稿の継続的な再取得（登録時の1回だけ）、全肯定APIの削除（旧クライアントがなくなった後に別途行う）。
