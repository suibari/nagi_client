# Spec Delta

## ADDED Requirements

### Requirement: API-10 おすすめの取得

AppViewはおすすめを `com.suibari.nagi.getRecommended` で返し、候補を「閲覧者の興味に近い投稿」または「投稿者本人とbotたんを除く5人以上がリアクションした投稿」としなければならない（MUST）。候補はトップ投稿に限り、botたんの投稿と閲覧者本人の投稿は含めない。botたんのスコアは候補条件に使わない。並びは新しい順、同じ人は1人1日1件とし、日付の境界は全肯定フィードと同じとする。1人1日1件の代表は、興味に近い投稿の中で最も近いもの、無ければ反応した人数が最も多いもの、それも並べば新しいものとする。興味の材料がない閲覧者と未サインインの閲覧者には、リアクション条件の候補だけを返す。タブ設定の `source` は `recommended` を受け付け、旧クライアントが書いた `affirmation` は `recommended` として読む。全肯定の取得APIは旧クライアントのために残す。

#### Scenario: 自分のリアクションだけの投稿

- **WHEN** 投稿者本人とbotたんだけがリアクションした投稿がある
- **THEN** その投稿をリアクション条件の候補にしない

#### Scenario: 旧クライアントのタブ保存

- **WHEN** 旧クライアントが `source: 'affirmation'` のタブを保存する
- **THEN** `recommended` として保存し、検証エラーにしない

### Requirement: API-11 おすすめの興味の材料

AppViewは興味の近さを、閲覧者の材料のいずれかとの埋め込みのコサイン距離が、埋め込みモデルごとに較正した閾値以下かどうかで判定しなければならない（MUST）。較正値のないモデルでは興味の候補を出さない。材料は、閲覧者のNagi投稿のうち埋め込み済みのものが5件以上あればその直近10件、なければ新規登録時の分析で読んだBluesky投稿の埋め込み（最大10件）とする。Bluesky投稿は本文を保存せず埋め込みだけを保存し、Nagiの投稿で測れるようになったら削除する。

#### Scenario: Blueskyから登録したばかりの人

- **WHEN** Nagiの投稿がまだ無く、新規登録時の分析でBluesky投稿を読めた人がおすすめを取得する
- **THEN** Bluesky投稿の埋め込みに近い投稿を候補に含める

#### Scenario: Nagiの投稿がたまった

- **WHEN** 閲覧者の埋め込み済みNagi投稿が5件以上になる
- **THEN** 興味の近さをNagi投稿で測り、Bluesky由来の埋め込みを削除する

#### Scenario: Bluesky投稿を読めなかった人

- **WHEN** ブロックや削除で新規登録時にBluesky投稿を読めず、Nagi投稿も足りない
- **THEN** リアクション条件の候補だけを返す
