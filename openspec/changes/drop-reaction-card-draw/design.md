# Design

## Context

動機は [proposal.md](proposal.md) のWhyを参照する。

- AppView（bsky-affirmative-bot main `d9e826e6`、2026-11-14確認）は、ドローの `source` に `my_nagi`・`reaction`・`anniversary` を持つ。`reaction` は当日の自分のリアクションのURIをPDSで確かめてから引かせる。
- おすそわけの価格は `packages/shared-configs/src/cardBoard.ts` にある。置いたときにもらうƵと取るときに払うƵは同じ値（N 1・R 3・SR 10・UR 30・AAR 100）。ボードに無いAARはbotたんの分として `CARD_SHELF_AAR_PRICE = 600` で受け取れる。
- 600Ƶの根拠（`docs/zenkatsu.md` 13.3）：供給1.5枚/日、余りがすべて溜まったときの流入≒4.3Ƶ/日。自力でAARを引くまでの期待値（約330日）より早いが、すぐには届かない額。コンプリートまでの日数の中央値をほとんど動かさず、運の悪い人の上限を決める。
- クライアントは `src/lib/cards/share-board.ts` の `BOT_AAR_PRICE` をヘルプの説明だけに使う。実際の価格はボードの `price` が正。

## Goals / Non-Goals

**Goals:**

- カードの入手を1日1枚にし、リアクションをカードの報酬から切り離す。
- 供給が減っても、botたんのAARに届くまでの日数を当初の狙いに保つ。

**Non-Goals:**

- ゼンカツのお休み日数・提出枚数の見直し（供給1枚/日でも14日目に3枚出せる。`docs/zenkatsu.md` 3.3）。
- 排出率、置いたときのƵ、ボードの他のカードの価格の変更。

## Decisions

### D1: リアクション枠は入口から報酬まで丸ごと外す

**課題**：入口だけ消すと、旧クライアントやリアクション後の処理が `source: "reaction"` を送り続ける。案内文だけ残ると、引けない枠を約束することになる。

**採用判断**：クライアントはリアクション後のドロー呼び出し・カード表示・失敗時の再試行・案内ダイアログ・「Next」の文言をすべて削除する。AppViewは `source: "reaction"` を拒否する。

**理由と制約**：過去にリアクション枠で引いたカードは所持の正本（AppView）にも公開控え（PDSのcardGet）にもあるので、消さない。`CardDrawSource` の型とPDSレコードの `source` は既存データを読むために `reaction` を残す。

### D2: botたんのAARは300Ƶにする

**課題**：600Ƶは供給1.5枚/日で決めた額で、1枚/日では届くまでが1.5倍に延びる。

**採用判断**：300Ƶにする。

**理由と制約**：レアリティ別の排出率・図鑑の枚数（N 12・R 9・SR 6・UR 2・AAR 1）・手元に3枚残して余りをすべて置く前提・はじめての30Ƶで、新しい人を4000回シミュレーションした（2026-11-14）。

| 供給             | 価格     | 届くまで（中央値） | 運の悪い10% | 自力で引く前に届く割合 | コンプリート（中央値／運の悪い10%） |
| ---------------- | -------- | ------------------ | ----------- | ---------------------- | ----------------------------------- |
| 1.5枚/日（従来） | 600Ƶ     | 252日              | 275日       | 46%                    | 233日／276日                        |
| 1枚/日           | 600Ƶ     | 378日              | 412日       | 46%                    | 349日／414日                        |
| 1枚/日           | 400Ƶ     | 291日              | 316日       | 55%                    | 285日／382日                        |
| 1枚/日           | **300Ƶ** | **242日**          | **264日**   | 61%                    | **249日／382日**                    |
| 1枚/日           | 250Ƶ     | 217日              | 235日       | 64%                    | —                                   |

- 300Ƶは、従来の「届くまで約8か月」とコンプリートの中央値（約8か月）を最もよく保つ。
- 自力で引く前に届く割合は46%から61%に上がる。自力でAARを引くまでの期待値が約330日から約500日へ延びたためで、botたんのAARが主な入手経路になるのは上限を決めるという当初の役割に沿う。
- 運の悪い10%のコンプリートはURの待ちで決まり（約382日）、300Ƶでもそれより早くはならない。コンプリートが簡単になりすぎない。
- ボードに置かれたAAR（100Ƶ）の3倍で、置かれたAARが優先される関係は保たれる。
- 既存の利用者は余りをすでに持っているため、この表より早く届く。シミュレーションはボードでN〜URを買う支出を含めないので、実際の到達はやや遅い。

### D3: drawStatusのリアクション枠

**課題**：AppViewの応答からリアクション枠を消すか、常に引けない状態で返すか。

**採用判断**：AppViewは `reaction` を応答から外す。クライアントは応答にあっても読まない。

**理由と制約**：クライアントを先に公開できる。lexiconの該当フィールドは任意項目なので、外しても旧クライアントは「引けない」と扱う（CARD-01の安全側）。

## Risks / Trade-offs

- 値下げの時点で600Ƶを目標に貯めていた人は、予定より早く受け取れる。値上げではないので、損をする人はいない。
- すでに600Ƶで受け取った人との差が生まれる。台帳には支払額が残る。

## 決定事項

- 価格は300Ƶとする（2026-11-14、利用者の合意）。
- 600Ƶで受け取った人へ差額は返さない（同上）。
