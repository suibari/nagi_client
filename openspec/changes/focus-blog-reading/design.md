# Design

## Context

共通シェルは通常、左ナビ・メイン・右ペインの3列で表示する。1180px以上では右ペインに検索とニュースまたはラジオが表示される。`/about` と `/write` 系には、右ペインを外してメインを広げる `shell-wide` がある。ブログ閲覧では中央と右の領域を合わせて記事を中央寄せにしていたため、記事の左端がフィードや一覧との間でずれていた。 [変更提案](proposal.md)

## Goals / Non-Goals

**Goals**

既存の共通シェルと記事コンポーネントを使い、ブログの表示領域と本文の読み幅をそれぞれ確保する。

**Non-Goals**

URLの配信構成、記事データ取得、公開・編集処理、ラジオの全体通知や未読管理は変更対象外とする。

## Decisions

### 共通シェルの中央ペインをそろえる

ブログ一覧と個別記事を `shell-wide` の対象から外し、共通シェルの中央ペインを記事に使う。ブログ閲覧時は既存の `SidebarRight` のマウントを抑える。個別記事は右側のグリッド列を余白として確保する。カバーや本文とコメントを中央ペイン内に収めることで、一覧から移動したときの基準線がそろう。

### 一覧のタグを画面幅に合わせて配置する

右ペインが出る幅では、一覧のメイン内に共通シェルと同じ右列と列間隔を設け、記事一覧と見出しを中央列、絞り込みタグを右列に置く。同じタグのナビゲーションを右ペインが出ない幅では記事一覧の前に配置する。タグの取得元、URLのクエリ、選択状態は今の一覧の状態を使う。既存のブレークポイントを使うことで、他の画面と同じ条件で右列が出る。

### 記事と記事一覧を先に読めるようにする

一覧は見出し・著者・日付を揃え、カバーの高さに上限を設ける。カードの区切りは既存テーマの細い線と余白を使う。記事に届いたリアクションは記事選びの手がかりとして残す。抜粋の生成には先頭見出しと本文を分ける既存処理を使い、著者が保存した概要を優先する。表示の見直しには Damir Sokolovsky（@heydamir）の unslop（CC BY 4.0）を参照した。

個別記事では既存の未ログイン向け紹介をコメントの後ろに置く。紹介の表示条件と認証復元中の制御を引き継ぐため、初回HTMLと画面遷移で同じ順序を使える。

### 表示処理に変更を収める

レイアウトは公開状態やセッションの有無に依存しない。既存記事の原文・翻訳、データ取得失敗時の表示や再試行は現在の処理を使い、レイアウトの判定に保存データや外部サービスへの書き込みを追加しない。 [BLOG-08 差分仕様](specs/blog-publication/spec.md)

## Risks / Trade-offs

- 広いカバーや長いタイトル・URLが狭い画面で横にはみ出す場合は、画像と可変列の幅や折り返しを調整する。端末幅の切り替え境界も確認する。 [UI-02](../../specs/ui-platform/spec.md#ui-02)
- 個別記事には静的HTMLとSPAフォールバックの入口がある。直接アクセス、クライアント内の遷移、戻る操作で同じ表示条件が使われることを確認する。 [BLOG-06](../../specs/blog-publication/spec.md#blog-06)

## Migration Plan

クライアントの通常リリースで適用する。切り戻しはシェルの表示条件とブログのスタイルを戻す。記事データの移行は不要。
