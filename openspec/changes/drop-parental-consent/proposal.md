# Proposal

## Why

Nagiは「18歳未満の方は保護者の同意を得てご利用ください」と、ログイン画面・利用規約・プライバシーポリシー・ゲスト投稿の同意文・生年月日の申告フォームで求めている。この要件は外部サービスの規約から来たもので、すでに根拠がない。

- 2026-07-26：AI機能に使っていたGemini APIの規約に合わせて「18歳以上のみ」とした。
- 2026-09-02：自動モデレーションがOpenAIに変わり、その規約に合わせて「13歳以上、18歳未満は保護者の同意」に改めた。同日、OpenAIの利用規約はAPI顧客の利用者には課されないと確認し、13歳の下限を撤回した。このとき保護者の同意だけが残った。
- 現在、文章生成は運営者が自宅で運用するモデルで行っている。未成年の保護は、未申告を未成年として扱い成人向けラベルをサーバで強制除外する仕組みで行っている。

運営者は保護者の同意の要件そのものを不要と判断した（2026-11-12）。

## What Changes

- ログイン画面から年齢の告知を外し、利用規約とプライバシーポリシーへの同意の文だけを残す。
- ゲスト投稿の同意文から「18歳未満の場合は保護者の同意を得たうえで、」を外す。
- 生年月日の申告フォームから保護者の同意の確認を外す。18歳未満の生年月日も確認なしで申告できる。未成年として扱う表示制御は変えない。
- 利用規約（冒頭の要約・第2条）とプライバシーポリシー（第5節の理由づけの段落・第10節）から保護者の同意の記述を外す（日本語・英語）。第10節の見出しは年齢確認の扱いに合わせて改める。
- 規約・ポリシーの最終更新日を更新する。
- **AppView（別リポジトリ）**：生年月日の申告で18歳未満に保護者の同意を必須にする検証をやめ、同意の日時を保存しない。既存の保存済みの同意日時の扱いは design.md のOpen Questionsで決める。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `auth-session`：AUTH-07に、ログイン画面の同意の文の条件（年齢の告知を置かない）を加える。
- `moderation-privacy`：MOD-01に、18歳未満の申告で保護者の同意を求めないことを加える。

## Impact

- クライアント：`src/routes/login/+page.svelte`、`src/lib/components/AgeAssuranceForm.svelte`、`src/lib/moderation/age.svelte.ts`、`src/lib/api/types.ts`、`src/lib/i18n/ja.ts`・`en.ts`、`src/routes/terms/*`、`src/routes/privacy/*`、`src/lib/legal/meta.ts`、関連テスト。
- AppView：`apps/nagi_appview/src/services/ageAssurance.ts`、lexiconの型（`parentalConsent` の説明）。DBの列 `parental_consent_at` は残す（削除は別に判断する）。
- 公開順序：AppViewを先に公開する。クライアントが先だと、18歳未満の申告がサーバに拒否される。
- 非対象：未申告を未成年として扱う仕組み、成人向けラベルの強制除外、生年月日の1度だけの申告。
