# 全肯定カード・ゼンカツ・名刺

## Purpose

### 機能概要

全肯定の体験を、集める・遊ぶ・分ける・記念日を祝う形で楽しむ機能群である。全肯定カードは1日1枚の取得と記念日の配布で集め、ゼンカツではお題に札を出してbotたんの総評を受け取る。点数や順位で利用者を比較せず、本人の発見や記録を残すことを重視する。

プロフィールの名刺は本人の紹介を画面・画像で共有する別用途だが、描画と共有画像の設計をこの分野で扱う。季節ごとの催しは [季節イベント](../seasonal-events/spec.md) で扱う。

### 機能一覧

| 機能                   | 役割・利用者ができること                               | 詳細要件                                  |
| ---------------------- | ------------------------------------------------------ | ----------------------------------------- |
| カード取得と図鑑       | 取得可能状態と本人の所持を共有し、図鑑へ反映する。     | [CARD-01](#card-01) / [CARD-02](#card-02) |
| ゲスト引継ぎと取得控え | 未ログインの結果を引き継ぎ、PDSへ公開控えを残す。      | [CARD-03](#card-03)                       |
| 祝いの演出             | 初回取得、レアリティ、所持の節目、記念日を祝う。       | [CARD-02](#card-02) / [CARD-04](#card-04) |
| ゼンカツ               | お題、札の選択、BONUS、総評と作者の意図を扱う。        | [CARD-05](#card-05)                       |
| 発見とリアクション     | コンボ・トロフィーの記録と、所有者向け反応一覧を出す。 | [CARD-06](#card-06)                       |

| プロフィール名刺       | 共通デザインで画面・保存PNG・OGPを生成する。           | [CARD-08](#card-08)                       |

### 主な利用の流れ

1. 本人のコレクションと今日の取得状態を読み、確認できた入口を表示する。
2. 今日のカードを引く、記念日カードを受け取る、またはゼンカツのお題へ札を出す。
3. AppViewで確定した結果を図鑑・記録・演出へ反映し、必要なPDS控えを作る。
4. 過去の結果は再閲覧として表示し、取得時だけの祝いを繰り返さない。

この文書は現行クライアントの振る舞いを整理する。設計判断は [design.md](design.md)、導入時の証跡は [コメント原文](../../reference/comment-snapshot/cards-zenkatsu-advent.md)、既知の不整合は [known-gaps.md](../../known-gaps.md) に分けて記録する。シナリオは確認条件であり、全外部環境での実行合格を示すものではない。

## Requirements

<a id="card-01"></a>

### Requirement: CARD-01 所持と取得状態の権威

カード所持はAppViewを権威とし、DID単位のコレクションを共有しなければならない（MUST）。未取得のままdrawStatusだけ得た場合に空の図鑑を取得済みとして作らない。本人と確認できたcanDrawだけで取得入口を出し、旧応答・公開フォールバックでは安全側に閉じる。

#### Scenario: OAuthの遅い復元

- **WHEN** 盤面やナビ初回表示の後でDIDが判明する
- **THEN** リアクティブな本人状態を更新して未ドロー表示へ反映する

#### Scenario: drawStatusの欠落

- **WHEN** 公開フォールバックに本人情報が含まれない
- **THEN** 引けると推定してボタンを出さない

<a id="card-02"></a>

### Requirement: CARD-02 日付境界・報酬・再試行

通常の取得・ゼンカツはJST4時をプレイ日境界とし、nextDrawAt等のサーバ状態に従って再取得しなければならない（MUST）。カードを引けるのは通常枠の1日1枚とし、リアクションで追加のカードを引く枠を持たない。記念日報酬は通常枠と区別し、抽選枠を消費しない。記念日報酬はログイン時に受け取り1枚ずつキューで表示する。

#### Scenario: 連続リアクション

- **WHEN** 通常枠のカードを引いた日に、他人の投稿やニュースへ続けてリアクションする
- **THEN** カードの取得や取得の案内を出さず、次に引ける時刻は通常枠の次の日付境界のままである

#### Scenario: 複数の記念日

- **WHEN** 同日に記念日カードを複数受け取る
- **THEN** モーダルを重ねず閉じるたび次へ進む

#### Scenario: リアクション枠で引いた過去のカード

- **WHEN** 廃止前にリアクション枠で引いたカードを図鑑や記録で開く
- **THEN** 所持と記録をそのまま表示する

<a id="card-03"></a>

### Requirement: CARD-03 取得控えとゲスト引継ぎ

PDSのcardGetは所持の正本でなく公開控え・リアクション対象でなければならない（MUST）。控え失敗でも所持は減らさず後で再試行する。未サインインで得た当日カードはログイン後に通常枠へ移し、成功するまで端末結果を消さない。

#### Scenario: 控えの書き込み失敗

- **WHEN** AppViewのドロー成功後にPDSが失敗する
- **THEN** カード所持を維持し、次回取得等で控えを拾い直す

#### Scenario: ゲストからの移行失敗

- **WHEN** claimが通信エラーになる
- **THEN** 当日結果を端末に残して再試行できる

<a id="card-04"></a>

### Requirement: CARD-04 演出と節目

レアリティごとの待ち・昇格色・振動・紙吹雪はcelebrationの共通契約に従わなければならない（MUST）。10%刻みの節目は直前所持数から初めて越えた場合だけ祝う。過去カード閲覧・重複・冪等再取得で取得演出を再発火しない。

#### Scenario: 取得済みの再応答

- **WHEN** 同日のドローを再取得する
- **THEN** 節目や初回演出を再度発火しない

#### Scenario: 履歴の閲覧

- **WHEN** 年表や他人の記録からカードを開く
- **THEN** draw演出と本人専用コメントを付けない

<a id="card-05"></a>

### Requirement: CARD-05 ゼンカツの非競争設計

ゼンカツはお題、札の選択、BONUS、総評を表示し、スコアや順位を出してはならない（MUST）。下位を否定する競争表示を避けるためである。作者の意図は初期状態で畳み、開くまで翻訳も始めない。送信失敗で選択へ戻っても任意の作者意図を保持する。

#### Scenario: 他人の作品閲覧

- **WHEN** 記録を開く
- **THEN** 札とbot総評を見せ、作者意図は本人が開くまで隠す

#### Scenario: 提出失敗

- **WHEN** select段階へ戻る
- **THEN** 書いた作者意図を失わない

<a id="card-06"></a>

### Requirement: CARD-06 未発見情報とリアクターの非公開

コンボ定義はクライアントへ配布せず、成立・発見済みの情報とサーバが許可したヒントだけを表示しなければならない（MUST）。トロフィーは種類別メダルと獲得回数に集約し、履歴は選択後に出す。cardGet/zenkatsuへのリアクター一覧はsubjectの持ち主だけへ表示する。

#### Scenario: 伏せコンボ

- **WHEN** 未発見の図鑑マスを開く
- **THEN** 返された枚数・発見済みヒントだけを出す

#### Scenario: 第三者閲覧

- **WHEN** 他人のカードニュースの反応を見る
- **THEN** 誰が誰へ反応したか追跡できる一覧を出さない

<a id="card-07"></a>

### Requirement: CARD-07 おすそわけと数の反映

だぶりの提供でƵを受け取り、未所持カードを受け取る操作はAppView確定値に従わなければならない（MUST）。ボードに置かれたAARが無いときは、botたんのAARを300Ƶで受け取れる。置かれたAARがあればそちらを優先し、通常のAARの価格で受け取る。複数提供の演出では1枚ずつ飛ばし、到着した時点で対応するƵ表示を増やす。

#### Scenario: 複数枚の提供

- **WHEN** サーバが受理した複数カードを演出する
- **THEN** 一括の数字飛びだけで終えず枚ごとの到着に合わせる

#### Scenario: botたんのAAR

- **WHEN** ボードに置かれたAARが無く、AARを持っていない人がボードを開く
- **THEN** AARを「ある」として300Ƶで表示し、ヘルプにも同じ額を示す

<a id="card-08"></a>

### Requirement: CARD-08 名刺DOM・保存PNG・OGP

名刺は同じ入力と固定デザインを共有し、DOMとCanvasを変更時に並べて確認しなければならない（MUST）。DOMはテーマ追従・QR無し、共有画像はライト固定・QRとブランドロゴ有りとする。保存PNGは91:55の1274×770、OGP寸法は別管理とする。タグは最大3つ、紹介が無ければ旧commentを最大120文字へ詰める。

#### Scenario: 分析未生成

- **WHEN** taglineもcommentも無い
- **THEN** 空の名刺を出さない

#### Scenario: Canvas生成

- **WHEN** 別originのアバターを読み込む
- **THEN** CORS付きで取得し、失敗はイニシャルへ戻す。保存失敗を無言で握り潰さない
