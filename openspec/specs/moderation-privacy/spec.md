# モデレーション・年齢・通報

## Purpose

### 機能概要

利用者が望まない内容への接触を減らし、年齢に応じた保護と、問題を運営へ伝える導線を提供する。自動判定には誤りがありうるため、なぜ伏せたかを断定しすぎず説明し、投稿者自身のCWとも整合させる。

Nagi投稿の年齢に基づく強制除外はAppViewが担当し、クライアントの表示設定では解除できない。ここでは本人の申告、成人の表示の好み、理由表示、通報、規約等の共通情報を扱う。

### 機能一覧

| 機能                       | 役割・利用者ができること                               | 詳細要件          |
| -------------------------- | ------------------------------------------------------ | ----------------- |
| 年齢申告                   | 未申告で利用を始め、本人が一度だけ生年月日を登録する。 | [MOD-01](#mod-01) |
| 表示の好み                 | 成人のラベル表示設定をDID別に保存・同期する。          | [MOD-02](#mod-02) |
| CWとの統合                 | 投稿者のぼかしと自動判定を重複させず保護を維持する。   | [MOD-02](#mod-02) |
| 理由の説明                 | 自動判定を可能性の表現で示し、不明な理由も扱う。       | [MOD-03](#mod-03) |
| 通報                       | 他人・botの投稿や本人投稿への反応を運営へ伝える。      | [MOD-04](#mod-04) |
| 規約・プライバシーポリシー | 日英の版・更新日・連絡先を共通管理する。               | [MOD-05](#mod-05) |

### 主な利用の流れ

1. 未申告の利用者には年齢登録の入口を示し、登録する場合は保存前に確認する。
2. 投稿のラベルと投稿者CW、本人設定を合わせて表示・警告・非表示を判断する。
3. 伏せる場合は理由を説明し、本人の年齢や非公開情報を第三者へ出さない。
4. 問題のある投稿や反応は、対象を選んで運営へ通報する。

この文書は現行クライアントの振る舞いを整理する。設計判断は [design.md](design.md)、導入時の証跡は [コメント原文](../../reference/comment-snapshot/moderation-privacy.md)、既知の不整合は [known-gaps.md](../../known-gaps.md) に分けて記録する。シナリオは確認条件であり、全外部環境での実行合格を示すものではない。

## Requirements

<a id="mod-01"></a>

### Requirement: MOD-01 年齢の真実源

生年月日は未申告でも利用開始でき、その場合は未成年扱いにしなければならない（MUST）。あとから1度だけ申告可能で、保存前に確認を挟み、サーバ確定値を採用する。18歳未満の生年月日でも保護者の同意を求めず、同意の記録も保存しない。本人だけへ返る日付を第三者に出さない。成人向けの強制除外はAppViewが担当し、クライアントだけの設定で解除できない。

#### Scenario: 未申告

- **WHEN** 利用開始時に生年月日を入れない
- **THEN** 未成年扱いで開始できる

#### Scenario: すでに申告済み

- **WHEN** 二重の申告でサーバに拒否される
- **THEN** 確定済み値を取り直し状態を合わせる

#### Scenario: 18歳未満の申告

- **WHEN** 18歳未満の生年月日を申告する
- **THEN** 保護者の同意を確認せずに受け付け、未成年として扱う

<a id="mod-02"></a>

### Requirement: MOD-02 DID別表示設定とCWの優先

成人の表示設定はDID別端末キャッシュへ即時保存しpreferencesと同期しなければならない（MUST）。全メディアに投稿者CWがある場合は一部の自動メディア警告を重ねないが、本人self-label、本文由来警告、hide指定は保つ。!hideは表示設定の対象外として残す。

#### Scenario: 二重のぼかし

- **WHEN** 全画像にCWがあり自動sexual判定もある
- **THEN** 同じメディアを理由に投稿全体を二重に隠さない

#### Scenario: 本文由来のラベル

- **WHEN** 画像CWのある投稿にhate等がある
- **THEN** 画像だけの警告と誤認して除かない

<a id="mod-03"></a>

### Requirement: MOD-03 理由の表現

自動判定の警告は理由を添え、誤判定がありうるため可能性として表現しなければならない（MUST）。!hideは性的表現と同じ文言へ寄せ、疑いを公の断定ラベルとして貼らない。不明ラベルは汎用理由にまとめ、同じ理由を重複させない。

#### Scenario: 未知のラベル

- **WHEN** 現在知らない自動ラベルが返る
- **THEN** 警告自体を消さず汎用文言を使う

#### Scenario: 同義の複数ラベル

- **WHEN** 同じ説明に対応するラベルが並ぶ
- **THEN** 同じ理由を1回だけ出す

<a id="mod-04"></a>

### Requirement: MOD-04 通報対象と通知先

他人やbotの投稿、本人投稿に付いた他人のリアクションを通報できなければならない（MUST）。通報は運営への送信で相手へ通知しない。自分自身のリアクションは対象選択に出さず、bot返信のFBや対象が1人の場合は適切に初期選択する。

#### Scenario: 本人の投稿

- **WHEN** 他人が付けたリアクションを運営へ伝える
- **THEN** 該当する送信者・絵文字を選び、本人の反応は除く

#### Scenario: 端末ゲスト投稿

- **WHEN** 運営管理外のローカル投稿を見る
- **THEN** 運営が扱える投稿と同じ通報操作を出さない

<a id="mod-05"></a>

### Requirement: MOD-05 法的文書の版

利用規約・プライバシーポリシーの更新日はlegal/metaへ集約し、実質的本文変更時だけ更新しなければならない（MUST）。ja/enで同じ日付を使い、相違時は日本語版を優先する。連絡先とサイトマップも同じメタデータを参照する。

#### Scenario: 翻訳表示

- **WHEN** 英語版の法的文書を表示する
- **THEN** 共通の更新日を使い、日本語優先の注記を保持する
