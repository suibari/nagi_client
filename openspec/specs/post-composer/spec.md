# 投稿・編集入力・下書き

## Purpose

### 機能概要

利用者が気持ちや記事を書き、届ける範囲を確認して投稿するための入力機能である。本文の装飾、添付、返信・引用、下書き、執筆のおたすけを一つの投稿体験へまとめる。書きかけを失わず、意図しない公開範囲の拡大や、作られなかった記事を成功と見せることを防ぐ。

外部アプリの共有メニューから受け取ったテキスト・URL・画像も、内容を確認して通常投稿へ取り込める。対応環境ではNagiのPWAインストールが必要になる。

通常投稿とブログは公開先・添付の扱いが異なり、3行日記は別形式の入力を使う。投稿結果の表示や外部へのコピー処理は関連仕様と連携する。

### 主な利用の流れ

1. 投稿モーダルを開き、書き方と公開範囲・返信できる人を選ぶ。ブログは執筆ページで書く（BLOG-07）。
2. 本文を書き、必要なら添付や返信・引用を加える。外部共有から始める場合は、必要ならログインし、投稿者・書きかけ・公開範囲を確認して取り込む。書きかけは自動保存される。
3. 公開先・メディア変換・必要権限等を確認し、送信可能な状態になったら投稿する。
4. 成功した投稿を画面へ反映して案内し、保存済み下書きを消す。失敗時は再試行に必要な内容を保つ。

この文書は現行クライアントの振る舞いを整理する。設計判断は [design.md](design.md)、導入時の証跡は [コメント原文](../../reference/comment-snapshot/post-composer.md)、既知の不整合は [known-gaps.md](../../known-gaps.md) に分けて記録する。シナリオは確認条件であり、全外部環境での実行合格を示すものではない。

## Requirements

<a id="post-01"></a>

### Requirement: POST-01 投稿範囲の単一軸

投稿範囲はkossori→feed→externalの排他的3段階でなければならない（MUST）。独立トグルの組み合わせが分かりにくかったため1本のゲージに統合した。記事公開は範囲の軸に含めず、書き方のblogタブで選ぶ。前回選択を優先し、未保存の / と /feed はkossori、それ以外はfeedを既定にする。

#### Scenario: 未保存のホーム投稿

- **WHEN** /feedで新規投稿を始める
- **THEN** kossoriを初期選択する

#### Scenario: 外部権限の確認待ち

- **WHEN** 前回externalでreadinessが未確定
- **THEN** externalを保ち、利用不能確定後だけfeedへ狭める

<a id="post-02"></a>

### Requirement: POST-02 スレッドの保存先と公開範囲

こっそりスレッドへの返信はAppView正本を引き継がなければならない（MUST）。ルートURIと旧投稿のkossoriで判定し、公開PDSへ漏らさない。公開スレッドにkossoriで返信する場合、未入力ならfeedへ切り替え、書きかけがあれば範囲を保持して送信を止める。返信の固定範囲を次の新規投稿の既定として保存しない。

#### Scenario: 書きかけの公開返信

- **WHEN** kossoriの内容がある状態で公開投稿を返信先にする
- **THEN** 黙って公開せず、理由を表示して送信を止める

#### Scenario: こっそりのネスト返信

- **WHEN** 返信のさらに返信を書く
- **THEN** 最初のルートと保存先を維持する

<a id="post-03"></a>

### Requirement: POST-03 モードとモーダル状態

simple/rich/blogの本文はその場で装飾し、別のプレビュー欄を持たない必要がある（MUST）。simpleは装飾ボタンを畳む。diaryは別の3行入力を使い、simple/richだけをポストの同一グループにまとめる。返信・引用・ゲストの文脈ではblog/diaryを選ばせない。blogはモーダルではなく執筆ページ（BLOG-07）で書き、ポストのモーダルとComposerを共有しない。defaultScopeは初期値としてだけ扱う。ポストのモーダルは閉じても書きかけと進行中の動画送信を保持する。

#### Scenario: ポスト側で返信先を選ぶ

- **WHEN** 執筆ページでブログを書きかけたまま、別の画面でポストのモーダルから返信する
- **THEN** ブログ側へ返信・引用文脈を混入させない

#### Scenario: Android入力

- **WHEN** Samsungキーボード等の環境で書く
- **THEN** 互換用のtextarea経路を使い、記事内の重ね表示は一覧表示に戻す

<a id="post-04"></a>

### Requirement: POST-04 こっそりと記事の制約

kossoriへ切り替えたら保持できない添付を外し、画像・リンクカード・外部公開を伴わせてはならない（MUST）。PDS上の参照レコードを持たずblobが保持されないためである。blogはこっそり、CW、引用・返信など記事化できない条件では理由を表示して送信を止め、動画を添付しない。

#### Scenario: 添付済みで範囲を縮小

- **WHEN** 画像を持つ投稿をkossoriへ切り替える
- **THEN** 添付をその場で外し、送信時にだけ無言で消さない

#### Scenario: 記事化不能

- **WHEN** blogタブで引用付きの内容を送ろうとする
- **THEN** 記事を作らず通常投稿だけ成功させる挙動にはせず、送信前に理由を示す

<a id="post-05"></a>

### Requirement: POST-05 記事タイトルとインライン添付

記事タイトルの真実源は本文先頭の見出しでなければならない（MUST）。独立入力は見出し未作成時の入口とし、既存見出しは読み取り専用で映す。本文の画像行とURL単独行はその位置に表示し、一覧へ重複させない。画像行削除は送信対象から外すがUndoのため編集中の添付は保持する。

#### Scenario: 見出しの追加

- **WHEN** タイトル入力があり本文に先頭見出しが無い
- **THEN** 送信時に#見出しを足し、facet化前に選択位置をずらす

#### Scenario: 画像行のUndo

- **WHEN** 本文から画像行を消して元に戻す
- **THEN** 削除中は投稿対象外、戻れば画像を再表示する

<a id="post-06"></a>

### Requirement: POST-06 下書きの保持と片付け

AppView下書きには本文等を保存し、画像blobは保存しない必要がある（MUST）。旧ローカル下書きの復元と画像CWの互換を維持し、添付を失ったNagi画像行は公開前に取り除く。投稿成功時は進行中の自動保存が終わるのを待ってから保存分を消す。引用の復元は現在の権限を再確認する。新規ブログでは独立したタイトル欄と記事メタ欄のタグも本人限定の下書きに保存・復元する。現在の内容が保存されたことを確認できる場合だけ保存済みとして扱う。

#### Scenario: 投稿と自動保存の競合

- **WHEN** 送信前から自動保存が進行中
- **THEN** 遅れて完了した保存が送信済みの下書きを復活させない

#### Scenario: リンクカード下書き

- **WHEN** サムネblobを持たず復元する
- **THEN** 保存済みタイトルと説明を先に出し、画像再取得失敗でも文字情報を残す

#### Scenario: タイトル・タグだけを書いて中断する

- **WHEN** 本文が空の新規ブログでタイトル欄または記事メタ欄のタグだけを入力し、下書き保存する
- **THEN** 手動保存と自動保存の対象になり、復元時にタイトル・タグを戻せる。本文先頭の見出しがある場合は従来どおり見出しをタイトルの正本とする

#### Scenario: 古い下書きと古い保存応答

- **WHEN** タイトル・タグのない旧下書きを復元する、または保存先が追加メタデータを保存・返却しない
- **THEN** 旧下書きは空のタイトル・タグとして復元できる。現在の空でないメタデータを復元できると確認できない場合は保存済みとみなさず、離脱警告を残す

#### Scenario: 保存中に内容を変更する

- **WHEN** 下書き保存の応答が返る前に本文・タイトル・タグ等を変更する
- **THEN** 応答は送信した内容だけの保存完了として扱い、現在の変更は次の保存で確認できるまで未保存とする

#### Scenario: 保存失敗と権限不足

- **WHEN** 通信失敗・権限不足・件数上限により現在の下書きを保存できない
- **THEN** 入力内容を維持し、保存できないことを表示する。現在の内容を保存済みと扱わない

#### Scenario: 保存中のアカウント切替

- **WHEN** 保存要求後にアカウントを切り替え、旧アカウントの保存応答が返る
- **THEN** 旧応答で切替先の入力を保存済みと扱わず、旧アカウントの下書きを切替先へ表示しない

<a id="post-07"></a>

### Requirement: POST-07 引用URLの取り扱い

通常モードでは文字列全体が内部スレッドURLのときだけ引用スロットに取り込み、本文へURLを残さない必要がある（MUST）。文章中のURLと画像ペーストを奪わない。引用可能なのは本人またはAppViewがisBotを付けた投稿とする。引用できない投稿のURLを単独で貼った場合は、URLをリンクとして本文に残す。他人のNagi投稿のURLは、単独で貼った場合も文中に書いた場合もリンクカードにしてはならない（MUST NOT）。相手の本文を自分の投稿の中に見せないためである。この制限はblogとBluesky専用の入力欄にも適用する。引用できない投稿のURLを残すときに案内は出さない。blogではURLを本文に残して通常のリンクカードにする（他人のNagi投稿を除く）。

#### Scenario: 文章とURLの混在

- **WHEN** スレッドURLを含む文章を貼る
- **THEN** 文章全体を引用として吸い上げない

#### Scenario: 引用取得失敗

- **WHEN** 引用URL単独を貼って取得に失敗する
- **THEN** 本文へ勝手にURLを戻さず、理由を出して貼り直しを選べるようにする

#### Scenario: 他人の投稿のURLを単独で貼る

- **WHEN** 本人でもbotたんでもない人の投稿のURLだけを貼る
- **THEN** 引用にせず、URLをリンクとして本文に残し、リンクカードを付けない

#### Scenario: 文中の他人の投稿のURL

- **WHEN** 本人でもbotたんでもない人の投稿のURLを文章の中に書く
- **THEN** リンクにするが、リンクカードを付けない

#### Scenario: ブログに他人の投稿のURLを書く

- **WHEN** blogの本文に、本人でもbotたんでもない人の投稿のURLだけの行を置く
- **THEN** リンクにするが、リンクカードを付けない

<a id="post-08"></a>

### Requirement: POST-08 投稿おたすけの非干渉

おたすけは書き進め中は具体的な良さ、未入力・削除時は本人の過去投稿や日記を材料に声をかけなければならない（MUST）。IME変換中は新規生成だけを止め、既存の吹き出しを跳ねさせない。×を押したら、ポストではモーダルを閉じるまで、ブログでは執筆ページを離れるまで再表示しない。古い本文への応答は捨て、生成失敗では静かに消える。おたすけは入力欄を覆ってはならない。ブログの執筆ページでは、PC幅は記事メタ欄の下に置き、スマホ幅は下部に出してその高さの分だけページ下に余白を確保する。

#### Scenario: 生成中の追加入力

- **WHEN** 応答前に本文を書き進める
- **THEN** 古い本文への生成結果を表示しない

#### Scenario: おたすけを押す

- **WHEN** ソフトウェアキーボードで入力中に操作する
- **THEN** 入力欄からフォーカスを奪わない

#### Scenario: PC幅でブログを書く

- **WHEN** 広い画面の執筆ページでおたすけが声をかける
- **THEN** 吹き出しは右カラムの記事メタ欄の下に出て、本文欄と重ならない

#### Scenario: スマホ幅でブログを書く

- **WHEN** 狭い画面の執筆ページで、本文の末尾を書いているときにおたすけが出る
- **THEN** 吹き出しの高さの分だけページ下に余白ができ、本文の末尾までスクロールして見える

<a id="post-09"></a>

### Requirement: POST-09 失敗の単位と投稿後の導線

失敗は再試行できる単位で表示し、内容拒否を通信障害と表示してはならない（MUST）。401・408・429は再試行可能な分類に残す。投稿後は楽観カードから確定カードへ追従し、表示不能なフィードでは投稿への導線を出す。最近使ったタグは成功後だけ記録する。

#### Scenario: 内容拒否

- **WHEN** サーバが内容による4xxを返す
- **THEN** 通信状態を確認という一律の文言にしない

#### Scenario: 検索画面からの投稿

- **WHEN** 現在の一覧に新規投稿を表示できない
- **THEN** 投稿を見失わないよう遷移可能な導線を出す

<a id="post-10"></a>

### Requirement: POST-10 返信できる人

公開範囲モーダルでは、公開範囲に関わらず、Nagiの投稿に返信できる人を **誰でも**・**botたんのみ**・**返信不可** から選べなければならない（MUST）。新規投稿・返信・ブログ・3行日記で選べ、通常の投稿と3行日記の入力は同じ選択を共有する。3行日記では日記レコード（`com.suibari.trilinesat.diary`）に `replyGate` を保存し、`botSilent` は付けない。「botたんのみ」は `replyGate: "bot"` を保存し、投稿者本人とbotたん以外の返信を受け付けない。「返信不可」は `replyGate: "nobody"` と `botSilent: true` を保存し、投稿者本人以外の返信を受け付けず、botたんも返事をしない。「誰でも」はどちらも付けない。選んだ値はブラウザに保存して次の投稿の初期値にし、保存がなければ「誰でも」とする。投稿後は編集でも変更できない。

#### Scenario: 返信不可で投稿

- **WHEN** 返信できる人を「返信不可」にして投稿する
- **THEN** 投稿に `replyGate: "nobody"` と `botSilent: true` を保存し、botたんも他の利用者も返信できない

#### Scenario: botたんのみで投稿

- **WHEN** 返信できる人を「botたんのみ」にして投稿する
- **THEN** 投稿に `replyGate: "bot"` だけを保存し、botたんは従来どおり返事をする

#### Scenario: 3行日記を返信不可で書く

- **WHEN** 3行日記の入力で返信できる人を「返信不可」にして書く
- **THEN** 日記レコードに `replyGate: "nobody"` を保存し、botたんも他の利用者も返信できない

#### Scenario: 選択の引き継ぎ

- **WHEN** 「返信不可」で投稿した後に、新しい投稿を始める
- **THEN** 返信できる人の初期値は「返信不可」になる

<a id="post-11"></a>

### Requirement: POST-11 Web Share Targetから通常投稿への取り込み

対応環境でインストールされたNagiは、テキスト・URL・画像の共有先として登録され、受信内容を通常投稿で確認・編集できなければならない（MUST）。テキストのみ・画像のみ・両者の共有を扱い、自動投稿してはならない。既存の書きかけを上書きせず、取り込み前に確認する。未ログイン時は端末内で一時保持し、ログイン後に取り込めるようにする。画像処理と上限はMEDIA-01/02、公開範囲はPOST-01/04に従い、黙って公開範囲を広げない。

#### Scenario: テキストとURLの共有

- **WHEN** 共有元からタイトル・本文・URLの一部または全部を受け取る
- **THEN** 空でない値をタイトル・本文・URLの順に改行でつないで通常投稿の本文へ取り込み、同一値の重複を除く。空の値を文字列として入れず、利用者が編集して投稿できる

#### Scenario: 画像のみとテキスト付き画像

- **WHEN** 対応画像を単独、複数、またはテキストと同時に共有する
- **THEN** 画像を既存の画像処理でプレビュー付き添付にし、本文があれば一緒に取り込む。通常投稿を開き、投稿操作を待つ

#### Scenario: 4枚上限と不正な画像

- **WHEN** 既存添付と合わせて4枚を超える画像、非対応ファイル、または処理できない画像を受け取る
- **THEN** 受信順で空き枚数までの有効画像を取り込み、超過・非対応・処理失敗を表示する。正常なテキストと画像および既存入力を維持し、成功したかのように黙って捨てない

#### Scenario: 書きかけがある

- **WHEN** 本文・添付・返信・引用などの既存の入力文脈がある状態で共有内容を取り込もうとする
- **THEN** 既存入力を変更する前に取り込み確認を表示する。承認した場合は本文を空行で区切って追記し、画像を残り枠へ追加する。返信・引用の文脈は自動的に解除せず、利用者が通常の新規投稿へ戻すまで取り込みを待つ。取り込みを見送っても既存入力を保つ

#### Scenario: ブログや日記の書きかけ

- **WHEN** ブログや3行日記の入力中に共有内容を受信する
- **THEN** その入力を保持し、共有内容は通常投稿へ取り込む。ブログや日記へ混入させない

#### Scenario: こっそりと共有画像

- **WHEN** 投稿範囲がこっそりの状態で画像付き共有を取り込もうとする
- **THEN** 画像を添付するには範囲変更が必要なことを示し、利用者が変更するまで受信画像を保留する。自動でfeedやexternalへ変更せず、既存のこっそり本文も保持する

#### Scenario: 未ログインとログイン失敗

- **WHEN** 未ログインで受信する、または受信後のログイン・権限確認に失敗する
- **THEN** 受信内容を同じ端末・origin内で一時保持してログインへ案内し、成功後に受信画面へ戻して取り込めるようにする。失敗を投稿成功と扱わず、画像をAppView下書きへ保存しない

#### Scenario: アカウント切替

- **WHEN** 受信後、取り込みが完了する前にアカウントが変わる
- **THEN** 旧アカウント向けの処理を切替先へ適用せず、現在の投稿者を示して再確認する。切替先へ自動で取り込んだり送信したりしない

#### Scenario: 再読込・複数の受信

- **WHEN** 同じ受信画面を再読込する、複数タブから開く、または別の共有を続けて受け取る
- **THEN** 受信単位を区別し、同じ共有を重複して本文・画像へ追加しない。別の共有で未処理の受信内容を上書きしない

#### Scenario: 空の共有と端末保存失敗

- **WHEN** 取り込める内容がない、または端末内の保存や読み取りが失敗する
- **THEN** 受信できなかった理由と共有し直す案内を表示し、既存入力を保つ。受信や取り込みが完了したと表示しない

#### Scenario: 一時データの片付け

- **WHEN** 取り込みが完了する、または利用者が受信内容を明示的に破棄する
- **THEN** 対応する端末内の一時データを削除する。画像処理の失敗分は再試行または破棄を選べるようにし、投稿の添付として渡したプレビューは利用中に破棄しない

<a id="post-12"></a>

### Requirement: POST-12 サイレントリプライと送信欄の表示

返信では、公開範囲モーダルでサイレントリプライを選べなければならない（MUST）。ONで返信すると `silentReply: true` を保存し、直接の返信先へ通知しない。直接の返信先がbotたんなら `botSilent: true` も保存し、botたんは返信しない。このことをトグルの説明文で示す。サイレントリプライは保存せず、返信先が変わるとOFFへ戻す。送信ボタンの横には返信の設定のボタンを置かず、制限やサイレントリプライが有効なときは公開範囲ボタンに示す。こっそりスレッドへの返信でもモーダルを開け、公開範囲は固定のまま返信の設定だけを選べる（POST-02）。編集では変更できない。

#### Scenario: botたんへのサイレントリプライ

- **WHEN** botたんの投稿に、サイレントリプライをONにして返信する
- **THEN** 返信に `silentReply: true` と `botSilent: true` を保存し、botたんはその返信に返事をしない

#### Scenario: 他の人へのサイレントリプライ

- **WHEN** botたん以外の投稿に、サイレントリプライをONにして返信する
- **THEN** 返信に `silentReply: true` だけを保存し、`botSilent` は付けない

#### Scenario: botたんへの通常の返信

- **WHEN** botたんの投稿に、サイレントリプライをOFF・返信できる人を「誰でも」のまま返信する
- **THEN** `silentReply` も `botSilent` も `replyGate` も付けず、botたんは従来どおり返事をする

#### Scenario: こっそりでbotたんへサイレントリプライ

- **WHEN** botたんの投稿に、こっそりでサイレントリプライをONにして返信する
- **THEN** こっそり投稿の作成にも `botSilent: true` を渡し、botたんは返事をしない

#### Scenario: サイレントリプライは引き継がない

- **WHEN** サイレントリプライをONにして返信した後に、別の投稿へ返信を始める
- **THEN** サイレントリプライはOFFから始まる

#### Scenario: 制限中の目印

- **WHEN** 返信できる人を「返信不可」にしている
- **THEN** 送信欄の公開範囲ボタンに、返信を制限していることを示す
