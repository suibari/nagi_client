# 投稿・編集入力・下書き

## Purpose

### 機能概要

利用者が気持ちや記事を書き、届ける範囲を確認して投稿するための入力機能である。本文の装飾、添付、返信・引用、下書き、執筆のおたすけを一つの投稿体験へまとめる。書きかけを失わず、意図しない公開範囲の拡大や、作られなかった記事を成功と見せることを防ぐ。

通常投稿とブログは公開先・添付の扱いが異なり、3行日記は別形式の入力を使う。投稿結果の表示や外部へのコピー処理は関連仕様と連携する。

### 機能一覧

| 機能                       | 役割・利用者ができること                                 | 詳細要件                                  |
| -------------------------- | -------------------------------------------------------- | ----------------------------------------- |
| 書き方の選択               | あっさり・しっかり・ブログ・3行日記を用途に応じて選ぶ。  | [POST-03](#post-03)                       |
| 公開範囲の選択             | こっそり・フィード・Blueskyにも、の3段階で届け先を示す。 | [POST-01](#post-01) / [POST-02](#post-02) |
| 本文と記事編集             | 装飾、見出し、本文内の画像・カード、添付を編集する。     | [POST-04](#post-04) / [POST-05](#post-05) |
| 下書き保存・復元           | 書きかけを保存し、投稿後は保存中のデータも片付ける。     | [POST-06](#post-06)                       |
| 返信・引用                 | 文脈を保持し、単独の内部URLを引用へ取り込む。            | [POST-02](#post-02) / [POST-07](#post-07) |
| ポストおたすけ             | 入力の妨げにならないタイミングで声をかける。             | [POST-08](#post-08)                       |
| 送信・エラー・投稿後の移動 | 送信できない理由を示し、投稿結果へ案内する。             | [POST-09](#post-09)                       |

### 主な利用の流れ

1. 投稿モーダルを開き、書き方と公開範囲を選ぶ。
2. 本文を書き、必要なら添付や返信・引用を加える。書きかけは自動保存される。
3. 公開先・メディア変換・必要権限等を確認し、送信可能な状態になったら投稿する。
4. 成功した投稿を画面へ反映して案内し、保存済み下書きを消す。失敗時は再試行に必要な内容を保つ。

この文書は現行クライアントの振る舞いを整理する。設計判断は [design.md](design.md)、導入時の証跡は [コメント原文](../../reference/comment-snapshot/post-composer.md)、既知の不整合は [known-gaps.md](../../known-gaps.md) に分けて記録する。シナリオは確認条件であり、全外部環境での実行合格を示すものではない。

## Requirements

<a id="post-01"></a>

### Requirement: POST-01 投稿範囲の単一軸

投稿範囲はkossori→feed→externalの排他的3段階でなければならない（MUST）。独立トグルの組み合わせが分かりにくかったため1本のゲージに統合した。記事公開は範囲の軸に含めず、書き方のblogタブで選ぶ。前回選択を優先し、未保存の / と /feed はkossori、それ以外はfeedを既定にする。

#### Scenario: 未保存のホーム投稿

- **WHEN** /feedで新規投稿を始める
- **THEN** kossoriを初期選択する

#### Scenario: 外部権限の確認待ち

- **WHEN** 前回externalでreadinessが未確定
- **THEN** externalを保ち、利用不能確定後だけfeedへ狭める

<a id="post-02"></a>

### Requirement: POST-02 スレッドの保存先と公開範囲

こっそりスレッドへの返信はAppView正本を引き継がなければならない（MUST）。ルートURIと旧投稿のkossoriで判定し、公開PDSへ漏らさない。公開スレッドにkossoriで返信する場合、未入力ならfeedへ切り替え、書きかけがあれば範囲を保持して送信を止める。返信の固定範囲を次の新規投稿の既定として保存しない。

#### Scenario: 書きかけの公開返信

- **WHEN** kossoriの内容がある状態で公開投稿を返信先にする
- **THEN** 黙って公開せず、理由を表示して送信を止める

#### Scenario: こっそりのネスト返信

- **WHEN** 返信のさらに返信を書く
- **THEN** 最初のルートと保存先を維持する

<a id="post-03"></a>

### Requirement: POST-03 モードとモーダル状態

simple/rich/blogの本文はその場で装飾し、別のプレビュー欄を持たない必要がある（MUST）。simpleは装飾ボタンを畳む。diaryは別の3行入力を使い、simple/richだけをポストの同一グループにまとめる。返信・引用・ゲストの文脈ではblog/diaryを選ばせない。ポストとブログのComposerは文脈を混ぜず、defaultScopeは初期値としてだけ扱う。共通モーダルは閉じても書きかけと進行中の動画送信を保持する。

#### Scenario: ポスト側で返信先を選ぶ

- **WHEN** 別のブログモーダルにも書きかけがある
- **THEN** ブログ側へ返信・引用文脈を混入させない

#### Scenario: Android入力

- **WHEN** Samsungキーボード等の環境で書く
- **THEN** 互換用のtextarea経路を使い、記事内の重ね表示は一覧表示に戻す

<a id="post-04"></a>

### Requirement: POST-04 こっそりと記事の制約

kossoriへ切り替えたら保持できない添付を外し、画像・リンクカード・外部公開を伴わせてはならない（MUST）。PDS上の参照レコードを持たずblobが保持されないためである。blogはこっそり、CW、引用・返信など記事化できない条件では理由を表示して送信を止め、動画を添付しない。

#### Scenario: 添付済みで範囲を縮小

- **WHEN** 画像を持つ投稿をkossoriへ切り替える
- **THEN** 添付をその場で外し、送信時にだけ無言で消さない

#### Scenario: 記事化不能

- **WHEN** blogタブで引用付きの内容を送ろうとする
- **THEN** 記事を作らず通常投稿だけ成功させる挙動にはせず、送信前に理由を示す

<a id="post-05"></a>

### Requirement: POST-05 記事タイトルとインライン添付

記事タイトルの真実源は本文先頭の見出しでなければならない（MUST）。独立入力は見出し未作成時の入口とし、既存見出しは読み取り専用で映す。本文の画像行とURL単独行はその位置に表示し、一覧へ重複させない。画像行削除は送信対象から外すがUndoのため編集中の添付は保持する。

#### Scenario: 見出しの追加

- **WHEN** タイトル入力があり本文に先頭見出しが無い
- **THEN** 送信時に#見出しを足し、facet化前に選択位置をずらす

#### Scenario: 画像行のUndo

- **WHEN** 本文から画像行を消して元に戻す
- **THEN** 削除中は投稿対象外、戻れば画像を再表示する

<a id="post-06"></a>

### Requirement: POST-06 下書きの保持と片付け

AppView下書きには本文等を保存し、画像blobは保存しない必要がある（MUST）。旧ローカル下書きの復元と画像CWの互換を維持し、添付を失ったNagi画像行は公開前に取り除く。投稿成功時は進行中の自動保存が終わるのを待ってから保存分を消す。引用の復元は現在の権限を再確認する。

#### Scenario: 投稿と自動保存の競合

- **WHEN** 送信前から自動保存が進行中
- **THEN** 遅れて完了した保存が送信済みの下書きを復活させない

#### Scenario: リンクカード下書き

- **WHEN** サムネblobを持たず復元する
- **THEN** 保存済みタイトルと説明を先に出し、画像再取得失敗でも文字情報を残す

<a id="post-07"></a>

### Requirement: POST-07 引用URLの取り扱い

通常モードでは文字列全体が内部スレッドURLのときだけ引用スロットに取り込み、本文へURLを残さない必要がある（MUST）。文章中のURLと画像ペーストを奪わない。引用可能なのは本人またはAppViewがisBotを付けた投稿とする。blogではURLを本文に残して通常のリンクカードにする。

#### Scenario: 文章とURLの混在

- **WHEN** スレッドURLを含む文章を貼る
- **THEN** 文章全体を引用として吸い上げない

#### Scenario: 引用取得失敗

- **WHEN** 引用URL単独を貼って取得に失敗する
- **THEN** 本文へ勝手にURLを戻さず、理由を出して貼り直しを選べるようにする

<a id="post-08"></a>

### Requirement: POST-08 投稿おたすけの非干渉

おたすけは書き進め中は具体的な良さ、未入力・削除時は本人の過去投稿や日記を材料に声をかけなければならない（MUST）。IME変換中は新規生成だけを止め、既存の吹き出しを跳ねさせない。×を押したらモーダルを閉じるまで再表示しない。古い本文への応答は捨て、生成失敗では静かに消える。

#### Scenario: 生成中の追加入力

- **WHEN** 応答前に本文を書き進める
- **THEN** 古い本文への生成結果を表示しない

#### Scenario: おたすけを押す

- **WHEN** ソフトウェアキーボードで入力中に操作する
- **THEN** 入力欄からフォーカスを奪わない

<a id="post-09"></a>

### Requirement: POST-09 失敗の単位と投稿後の導線

失敗は再試行できる単位で表示し、内容拒否を通信障害と表示してはならない（MUST）。401・408・429は再試行可能な分類に残す。投稿後は楽観カードから確定カードへ追従し、表示不能なフィードでは投稿への導線を出す。最近使ったタグは成功後だけ記録する。

#### Scenario: 内容拒否

- **WHEN** サーバが内容による4xxを返す
- **THEN** 通信状態を確認という一律の文言にしない

#### Scenario: 検索画面からの投稿

- **WHEN** 現在の一覧に新規投稿を表示できない
- **THEN** 投稿を見失わないよう遷移可能な導線を出す
