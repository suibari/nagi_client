# 日記・気分・3行日記

## Purpose

### 機能概要

利用者が過去の投稿を振り返り、その日の出来事や気分の変化を読み取れるようにする。日記ページでは月カレンダー・感情グラフ・botたんの日記を同じ日付で辿れ、気分の解釈が違う場合は本人が修正できる。3行日記では、その日を短い3つの文章と画像で記録する。

活動の日付はAppViewの設定に従う一方、3行日記はTriLinesAt互換の正午区切りである。二つの日付境界は目的が異なるため共通化しない。

| ------------------------ | -------------------------------------------------------- | --------------------------------------------- |
| 日付・月の移動           | URL、カレンダー、グラフ、詳細を同じ選択へ揃える。        | [DIARY-01](#diary-01)                         |

### 主な利用の流れ

1. 月を選び、カレンダーまたは感情グラフから日付を選ぶ。
2. その日の日記・投稿・気分を見比べ、必要なら気分を修正する。
3. 3行日記を書く場合は別の入力モードで3行を埋め、必要ならbotたんへ相談する。
4. 本人PDSの互換レコードへ保存し、Nagiで取り込まれた表示から振り返る。

この文書は現行クライアントの振る舞いを整理する。設計判断は [design.md](design.md)、導入時の証跡は [コメント原文](../../reference/comment-snapshot/diary-trilines.md)、既知の不整合は [known-gaps.md](../../known-gaps.md) に分けて記録する。シナリオは確認条件であり、全外部環境での実行合格を示すものではない。

## Requirements

<a id="diary-01"></a>

### Requirement: DIARY-01 日付・月・表示選択

日記ページはmonthとdateをURLへ反映し、月カレンダーと感情グラフの選択を共有しなければならない（MUST）。dateが年表指定と併存する場合はdateを優先する。選択解除で表示月を失わず、詳細内部のクリックやタブ切替は選択を解除しない。

#### Scenario: 同一路線の日付遷移

- **WHEN** 年表から別の日記へ移動する
- **THEN** 選択日と月をURLに合わせて更新する

#### Scenario: Escによる解除

- **WHEN** 日付を選択してからEscを押す
- **THEN** dateを解除してもmonthを保つ

<a id="diary-02"></a>

### Requirement: DIARY-02 活動の量と気分の分布

投稿量は受け取った1年の非ゼロ日件数の分布を3等分したドットで示し、固定件数の閾値にしてはならない（MUST）。気分は平均でなく中央値と中央50%帯で示す。同じ日に明暗が混在しても0付近に潰さない。気分なし日は無地、投稿なし日は線を切る。

#### Scenario: 単一の気分

- **WHEN** その日に点が1つだけある
- **THEN** 高さ0の不可視帯にせず丸として示す

#### Scenario: 投稿なしの間隔

- **WHEN** 2日の気分の間に投稿のない日がある
- **THEN** 中央値の線を連続させない

<a id="diary-03"></a>

### Requirement: DIARY-03 日の窓とタイムゾーン

気分の日の窓はAppViewが返した日別windowsを最優先にし、無ければ指定timeZoneとstartHour、さらに端末時刻と22時へフォールバックしなければならない（MUST）。夏時間や設定変更による24時間以外の窓も扱い、投稿時刻・目盛り・横バーを同じ時計に揃える。

#### Scenario: 日区切りを変更した過去日

- **WHEN** AppViewがその日の専用windowを返す
- **THEN** 現在設定で過去日を再計算しない

#### Scenario: 自動TZ

- **WHEN** 本人が手動選択中または旧AppViewである
- **THEN** 端末の自動検出値を上書き送信しない

<a id="diary-04"></a>

### Requirement: DIARY-04 気分の補間と編集

横バーは時間に対してvalenceを補間し、端の外側は最寄りの気分を延長しなければならない（MUST）。同じ分の点は平均でまとめ、色そのものの混合で中間スケールを飛ばさない。本人の修正成功は表示と取得済みキャッシュの両方へ反映し、点削除も扱う。

#### Scenario: 正負の気分の間

- **WHEN** +5から-5へ推移する
- **THEN** 中間のvalence色を順に通る

#### Scenario: 本人の修正

- **WHEN** 気分の保存に成功する
- **THEN** 現在月とキャッシュの値を一緒に差し替える

<a id="diary-05"></a>

### Requirement: DIARY-05 3行日記の正本と日付

TriLinesAt互換のcom.suibari.trilinesat.diaryを本人PDSの正本とし、Nagi投稿への複製を作ってはならない（MUST）。3行全てを必須とし、行画像は1MB以下、Nagiからは掲載opt-inをtrueにする。日付は端末の正午→翌正午を暦で計算する。

#### Scenario: 深夜の執筆

- **WHEN** 正午前に3行日記を書く
- **THEN** 前の正午から始まる日のレコードにする

#### Scenario: Nagiで保存

- **WHEN** 3行日記を書き終える
- **THEN** TriLinesAtと共有する同じcollectionへ書く

<a id="diary-06"></a>

### Requirement: DIARY-06 相談の材料と翻訳

3行日記の相談材料は日記日付の0時から今までの投稿を使い、正午境界だけで午前中の出来事を捨ててはならない（MUST）。翻訳は行を改行で結合した本文を使い、行数一致時だけ各行へ割り当てる。不一致なら訳文を一続きにし画像を下へまとめる。

#### Scenario: 深夜の相談

- **WHEN** 翌日の正午前に相談する
- **THEN** 前日0時から今まで、最大約36時間を材料にする

#### Scenario: 翻訳の行数ずれ

- **WHEN** 翻訳結果が3行にならない
- **THEN** 画像を誤った行へ割り振らない

<a id="diary-07"></a>

### Requirement: DIARY-07 サンプルと読み上げ

about等の架空データはAPIを呼ばず、実在しない投稿・日記リンクを付けてはならない（MUST）。ラベル付き投稿の本文は横バーの読み上げにも露出させない。投稿一覧と横バーの点は同じ投稿へジャンプする。

#### Scenario: サンプルの点操作

- **WHEN** 架空の気分点を押す
- **THEN** 外部レコードへ移動せず表示内の対応行へ移る
