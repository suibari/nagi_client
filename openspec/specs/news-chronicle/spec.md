# ニュース・年表

## Purpose

### 機能概要

ニュースは外の出来事を会話のきっかけとして届ける機能、年表は本人の投稿や活動の節目を振り返る機能である。ニュースでは話しやすい記事とbotたんのコメントを示し、引用して自分の言葉を書けるようにする。年表では過去の記録を古い順に並べ、今の節目から開いて年月のスクラバーで過去へ移れるようにし、その頃の世間の出来事も補足する。

公開ニュースと本人向け年表では可視性や既読単位が異なる。生成・承認・集計は外部サービスが担当し、本仕様は選定・表示・引用・URL受付・既読を扱う。

### 主な利用の流れ

1. ニュース一覧またはサイドバーのおすすめを読む。
2. 必要なら記事を開いて引用投稿・共有をする。URL投稿はpreviewを確認して追加する。
3. 振り返りたい場合は本人の年表へ移る。最新の節目から表示され、スクラバーで過去の月へ移って節目を読む。
4. 表示できたニュース位置や読み込めた年の既読を保存し、未表示のニュースや読み込めなかった年は未読として残す。

この文書は現行クライアントの振る舞いを整理する。設計判断は [design.md](design.md)、導入時の証跡は [コメント原文](../../reference/comment-snapshot/news-chronicle.md)、既知の不整合は [known-gaps.md](../../known-gaps.md) に分けて記録する。シナリオは確認条件であり、全外部環境での実行合格を示すものではない。

## Requirements

<a id="news-01"></a>

### Requirement: NEWS-01 サイドバー選定と順序

ニュース表示はbotのcreatedAtを優先した降順とし、同時刻は安定順を保たなければならない（MUST）。右サイドバーは最新候補の6時間以内からtalkScore→未読→関心おすすめ→新しい順で1件を選ぶ。talkScore無しは最下位とする。ラジオと同時刻の枠は本人向けラジオを優先する。

#### Scenario: 古い高得点記事

- **WHEN** 最新スロット外に高talkScoreがある
- **THEN** その記事を居座らせない

#### Scenario: 同点候補

- **WHEN** talkScoreが同じで既読状態が異なる
- **THEN** 未読記事を優先する

<a id="news-02"></a>

### Requirement: NEWS-02 既読と初回描画

ニュース既読はDID別に同期し、guestと混ぜず、画面を開いた時点で表示基準を凍結しなければならない（MUST）。急ぎの情報ではないためナビバッジと先回りの未読pollを持たない。静的seedは初期値だけとし、hydration後はviewer別に取り直す。

#### Scenario: 一覧を読む

- **WHEN** 表示済みの最新位置を保存する
- **THEN** 同じ画面にある未読マークを途中で消さない

#### Scenario: OAuth復元待ち

- **WHEN** guestから本人状態へ切り替わる
- **THEN** 本人の既読を確定するまで基準の凍結を待つ

<a id="news-03"></a>

### Requirement: NEWS-03 コメント・共有・投稿受付

ニュースコメントはニュース本体への引用投稿とし、Blueskyへ同時投稿してはならない（MUST）。合成botコメントURIは表示専用で、リアクションはニュース本体をsubjectにする。共有キャンセルは成功コピーと区別する。URL投稿はpreview後のURL編集で旧previewを無効にし、受付成功後に一覧を更新する。

#### Scenario: URLの書き換え

- **WHEN** preview取得後に別URLへ変える
- **THEN** 古い内容のまま追加させない

#### Scenario: 履歴取得失敗

- **WHEN** 投稿フォームの履歴APIが落ちる
- **THEN** 新規URLの追加自体は可能にする

<a id="news-04"></a>

### Requirement: NEWS-04 索引対象の統一

ニュースentries・load・sitemapは同じ索引対象取得関数を使い、ビルド中は共有しなければならない（MUST）。上限1500件、cursor停滞と回数の両方を制限する。取得失敗で全体ビルドを落とさず、空の一覧をindexしない。成人向けと検索公開同意の無い投稿者情報を静的HTMLへ混入させない。

#### Scenario: 公開直後のニュース

- **WHEN** まだプリレンダされていない記事を開く
- **THEN** 匿名APIで取得可能な公開記事を表示する

#### Scenario: 索引APIの不調

- **WHEN** AppViewから取得できない
- **THEN** 空の取得結果として扱い、空殻を検索対象にしない

<a id="chron-01"></a>

### Requirement: CHRON-01 順序・見出し・文脈ニュース

年表はサーバの古い順を保ち、年をまたぐページはidで重複除去しなければならない（MUST）。固定kindはi18n、LLM生成kindだけはサーバの文字列を使う。news_contextは月内最後のまとめの下の補足で、独立した日付の節目として扱わない。

#### Scenario: 同じ年の追加ページ

- **WHEN** 既存idを含むページが届く
- **THEN** 見出しと項目を二重に出さない

#### Scenario: 表示言語変更

- **WHEN** 固定kindを持つ過去の年表を開く
- **THEN** 作成時言語に固定せず表示言語へ追従する

<a id="chron-02"></a>

### Requirement: CHRON-02 年単位の既読と安全な演出

年表は年全体を読み込めたページだけを既読にし、未表示の年を巻き込んではならない（MUST）。本人の年表は開いた時点で全年を読み込むため、読み込めた年はすべて既読になる。旧端末の既読は全項目を読んだ年だけ移す。世代の古い応答で最新既読を上書きしない。reduced-motionでは観測を止め、出現・拡大の演出はいずれも基底状態を読める状態（opacityを0にせず、文字を縮めない）にする。

#### Scenario: 一部だけ読んだ旧履歴

- **WHEN** 年の全項目を読んでいない
- **THEN** その年全体を既読へ移行しない

#### Scenario: 動きを減らす設定

- **WHEN** animation:noneが適用される
- **THEN** 節目が透明のまま残らず、年の数字と節目のタイトルも通常の大きさで読める

#### Scenario: 全年の読み込み

- **WHEN** 本人が年表を開き、全年のページを読み込めた
- **THEN** 読み込めた年はスクロールで表示したかに関わらず既読になる

#### Scenario: 途中の年で読み込みに失敗

- **WHEN** 古い年から順に読み込む途中でページの取得に失敗する
- **THEN** 読み込めた年だけを既読にし、失敗した年以降は未読のまま残す

<a id="chron-03"></a>

### Requirement: CHRON-03 今から始まる全年表示

本人の年表は開いたときに全年のページを古い順に読み込み、読み込み終えたら最新の節目が見える位置（年表の末尾）を初期位置にしなければならない（MUST）。並び順はCHRON-01どおり古い順のままとする。読み込み中は読み込み中であることを示す。途中で取得に失敗した場合は、読み込めた年を表示したまま末尾に失敗と再試行の操作を出し、再試行では失敗した年から続きを読む。紹介ページのサンプルは初期スクロールを行わない。

#### Scenario: 数年分ある年表を開く

- **WHEN** 2024年から今年までの節目がある本人が年表を開く
- **THEN** 全年を読み込んだ後、今年の最後の節目が画面内に入った状態で表示される

#### Scenario: 途中の年で失敗

- **WHEN** 3年分のうち2年目の取得に失敗する
- **THEN** 1年目を表示したまま末尾に失敗と再試行を出し、再試行で2年目から読み直す

#### Scenario: 紹介ページのサンプル

- **WHEN** 紹介ページで年表のサンプルを表示する
- **THEN** ページのスクロール位置を年表の末尾へ動かさない

<a id="chron-04"></a>

### Requirement: CHRON-04 年のスクラバー

本人の年表は節目が1件以上あるとき、画面右端に縦のスクラバーを常に表示しなければならない（MUST）。年と節目がある月の目盛りを本文内の位置に比例して並べ、年を月より強く示す。混み合うラベルは年を優先して間引く。現在位置をつまみで示し、ドラッグとレールのクリック・タップで対応する位置へ移り、ドラッグ中は年月を大きく示す。上下キー・PageUp/PageDownで前後の節目がある月の最初の節目へ、Home/Endで先頭・末尾へ移れる。支援技術には年月を現在値とするスライダーとして伝える。1年分でも表示し、紹介ページのサンプルでは表示しない。補足ニュースを独立した月の移動先にしない。

#### Scenario: つまみを過去へ動かす

- **WHEN** 末尾から2024年6月の位置までつまみをドラッグする
- **THEN** 年表が対応する位置へスクロールし、ドラッグ中は「2024年6月」（英語表示では同等の年月）が大きく示される

#### Scenario: 普通にスクロールする

- **WHEN** スクラバーを使わずに年表をスクロールする
- **THEN** つまみが現在位置に追従し、支援技術へ伝える年月も対応する月に更新される

#### Scenario: キーボードで移動する

- **WHEN** スクラバーにフォーカスしてHomeキーを押す
- **THEN** 最初の年の見出しへ移り、スライダーの値は最初の節目の年月になる

#### Scenario: 最新の位置へ戻る

- **WHEN** スクラバーにフォーカスしてEndキーを押す
- **THEN** 最新の節目が見える末尾へ移り、スライダーの値は最新の節目の年月になる

#### Scenario: 1年分だけの年表

- **WHEN** 節目が今年の分しかない
- **THEN** 年と節目がある月の目盛りを持つスクラバーを表示する

#### Scenario: 前後の月へ移動する

- **WHEN** 2025年12月にいてArrowDownまたはPageDownを押し、次に節目がある月が2026年2月である
- **THEN** 2026年2月の最初の節目へ移る。そこからArrowUpまたはPageUpを押すと2025年12月の最初の節目へ移る

#### Scenario: 月ラベルが混み合う

- **WHEN** 狭い画面で年と月のラベルが重なる
- **THEN** 年のラベルを優先して重なるラベルを間引き、ラベルを省いた月もキー操作の移動先として残す

#### Scenario: 月の補足ニュース

- **WHEN** 月まとめの下に同月のnews_contextがある
- **THEN** そのニュースのために月の目盛りや移動先を増やさない

#### Scenario: 空または紹介用の年表

- **WHEN** 節目がない、または紹介ページのサンプルを表示する
- **THEN** スクラバーを表示しない

#### Scenario: 1か月だけの年表

- **WHEN** すべての節目が同じ月にある
- **THEN** スクラバーを表示し、年月の値をその月に保ったまま先頭から末尾まで移動できる

<a id="chron-05"></a>

### Requirement: CHRON-05 スクロールに応じた強調

年表の年の数字と節目のタイトルは、画面の中央へ近づくほど大きく濃く、離れるほど小さく淡く表示しなければならない（MUST）。年の数字は画面端の0.55倍から中央の等倍（約1.8倍）、節目のタイトルは画面端の0.72倍から中央の等倍（約1.4倍）とし、日付・吹き出し・カード・ニュース・リンクの大きさは変えない。拡大で行の高さや周囲の配置を動かしてはならない。動きを減らす設定、またはscroll-driven animationに対応しないブラウザでは演出を行わず、通常の大きさの静的表示にする。

#### Scenario: 年の数字が中央を通る

- **WHEN** 年の見出しが画面下端から中央へスクロールしてくる
- **THEN** 数字が徐々に大きく濃くなり、中央を過ぎると小さく淡く戻る

#### Scenario: 長いタイトル

- **WHEN** 2行に折り返す節目のタイトルが中央で拡大される
- **THEN** 本文の幅からはみ出さず、下の吹き出しやカードの位置も動かない

#### Scenario: 非対応ブラウザ

- **WHEN** animation-timelineに対応しないブラウザで年表を開く
- **THEN** 年の数字と節目のタイトルを通常の大きさで静的に表示する
