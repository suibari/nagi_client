# 表示言語・翻訳・テーマ

## Purpose

初回描画の安定、翻訳の一括取得と設定、テーマ適用を定義する。

この仕様は導入時点の実装・コメントから復元した現状の基準である。根拠と詳細な設計判断は [design.md](design.md)、確認された不整合は [known-gaps.md](../../known-gaps.md) を参照する。記載するシナリオは確認条件であり、今回すべての外部サービスを実行検証したという意味ではない。

## Requirements

### Requirement: I18N-01 静的描画の決定性

SSRとhydration直後は日本語・JST固定の絶対日付を使い、ブラウザ初期化後だけ端末言語・時刻に切り替えなければならない（MUST）。ビルド時点の今日/昨日/今年を焼き込んではならない。

#### Scenario: 異なるTZでのビルド

- **WHEN** UTCのビルド機でJSTの日付を描画する
- **THEN** 同じ入力から同じ静的HTMLを生成する

#### Scenario: 数日後の初回表示

- **WHEN** 過去にビルドされたHTMLを開く
- **THEN** ビルド日の今日という表示を引き継がない

### Requirement: I18N-02 初回テーマとCSP

保存済みテーマ・ロケールは初回描画前に外部theme-init.jsで適用しなければならない（MUST）。インラインscriptの固定ハッシュを増やさずscript-src selfのCSPへ対応する。読み取り失敗時は静的なlang等の既定を残す。

#### Scenario: 保存済みテーマ

- **WHEN** ダーク設定で再訪する
- **THEN** 初期の明色点滅を抑える

#### Scenario: 保存値の不正

- **WHEN** ロケールを読み取れない
- **THEN** 静的langのフォールバックを壊さない

### Requirement: I18N-03 言語設定の単位

UI言語、投稿言語、翻訳先、翻訳プロバイダー、自動翻訳はそれぞれの用途として扱わなければならない（MUST）。対応言語コードは正規化し、browser指定はブラウザ言語から対応値を選ぶ。アカウント同期する言語設定は一組として版を管理し、旧キー移行はAppView未設定の最初だけ行う。

#### Scenario: 地域付き言語

- **WHEN** en-US等の値を受け取る
- **THEN** 対応する基底言語へ正規化する

#### Scenario: 設定の同期

- **WHEN** 旧端末4キーから移す
- **THEN** 何度も旧値でサーバ値を上書きしない

### Requirement: I18N-04 一括翻訳と競合

翻訳対象は会話・表示中バブル・通常投稿・引用の描画順に重複除去してまとめ、例外的な同tick要求も個別APIへ戻さない必要がある（MUST）。既に翻訳済み・処理中の対象を再送しない。原文とCID、対象言語・providerの条件を取り違えず、古い応答を新しい表示へ混ぜない。

#### Scenario: 同じ投稿を複数箇所表示

- **WHEN** 同tickに翻訳を要求する
- **THEN** 対象を共有してまとめる

#### Scenario: 通知の翻訳待ち

- **WHEN** まだ訳文が無い
- **THEN** 原文を表示し通知一覧に過剰な翻訳状態操作を出さない

### Requirement: I18N-05 フォールバックと本文の整合

翻訳待ち・失敗は原文へ戻り、利用可能な英訳キャッシュは最終訳を待つ間の先行表示に使える必要がある（MUST）。訳文へ原文facetを当てない。ブログ一覧は既存キャッシュのみ、記事本文は原文静的HTMLを残したhydration後、3行日記は行数一致を確認する。

#### Scenario: 訳文の長さが変化

- **WHEN** 原文とbyte長が異なる訳文を表示する
- **THEN** 原文のmentionや装飾範囲をそのまま適用しない
