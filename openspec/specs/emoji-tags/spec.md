# 絵文字・タグ・生成UI

## Purpose

### 機能概要

言葉に加えて絵文字で反応し、タグで話題を見つけやすくする機能群である。利用者が日本語・英語の短い語から絵文字を探し、よく使うものをパレットへ整理して、入力やリアクションに使えるようにする。タグも同じようにお気に入り・最近使ったものから挿入できる。

カスタム絵文字の公開定義は本人PDS、検索や生成依頼はAppView、お気に入りはアカウント同期と端末キャッシュを使う。生成そのもののGPU運用はこのクライアントの責務外である。

### 機能一覧

| 機能                   | 役割・利用者ができること                                                 | 詳細要件                                      |
| ---------------------- | ------------------------------------------------------------------------ | --------------------------------------------- |
| 絵文字検索             | 1文字日本語・英語・意味からUnicodeとカスタム絵文字を探す。               | [EMOJI-01](#emoji-01) / [EMOJI-02](#emoji-02) |
| お気に入り・履歴       | 順序を保ってパレットへ登録し、連続選択や並べ替えを行う。                 | [EMOJI-03](#emoji-03)                         |
| カスタム絵文字登録     | 本人PDSへBluemojiとNagi識別情報を保存する。                              | [EMOJI-04](#emoji-04)                         |
| AI生成結果の登録       | 進行状況と最新候補を示し、名前等を編集して登録する。                     | [EMOJI-05](#emoji-05)                         |
| タグの正規化と履歴     | 検索・ミュート・保存に共通する形へ揃える。                               | [TAG-01](#tag-01)                             |
| タグ挿入と文脈メニュー | パレットから挿入し、本文のタグからお気に入り・タブ・ミュートを操作する。 | [TAG-02](#tag-02)                             |

### 主な利用の流れ

1. 入力中の候補、絵文字ピッカー、タグパレットのいずれかを開く。
2. 検索または履歴から選び、必要ならお気に入りへ保存・並べ替えする。
3. 本文へ挿入するかリアクションとして送信する。最近タグは投稿成功後に積む。
4. 新しい絵文字が必要なら生成を依頼し、結果の名前等を確認して本人PDSへ登録する。

この文書は現行クライアントの振る舞いを整理する。設計判断は [design.md](design.md)、導入時の証跡は [コメント原文](../../reference/comment-snapshot/emoji-tags.md)、既知の不整合は [known-gaps.md](../../known-gaps.md) に分けて記録する。シナリオは確認条件であり、全外部環境での実行合格を示すものではない。

## Requirements

<a id="emoji-01"></a>

### Requirement: EMOJI-01 日本語・英語検索

Unicode検索は内蔵検索だけに依存せず、ja/enを結合した索引で1文字日本語と英語を扱わなければならない（MUST）。NFKC、小文字、ひらがな→カタカナで正規化し、完全一致→前方一致→部分一致、同種なら表示名→shortcode→タグを優先する。

#### Scenario: 1文字の検索

- **WHEN** 炎で絵文字を検索する
- **THEN** 2文字未満を捨てず候補を返す

#### Scenario: 言語をまたぐ検索

- **WHEN** 日本語UIからfireと入力する
- **THEN** 英語キーワードでも検索できる

<a id="emoji-02"></a>

### Requirement: EMOJI-02 カスタム検索と登録直後

サジェストはカスタム絵文字をUnicodeより先にし、本人PDSの未取り込み絵文字も名前一致で補わなければならない（MUST）。既存結果と重複させず、保存済み履歴はAppViewで再解決して削除済み・規格外だけを除く。

#### Scenario: 登録直後

- **WHEN** AppViewにまだ取り込まれていない本人絵文字を検索する
- **THEN** PDSキャッシュから補ってすぐ利用できる

<a id="emoji-03"></a>

### Requirement: EMOJI-03 お気に入りとパレット操作

お気に入りの配列順を表示順に使い、重複追加や満杯時に既存要素を黙って落としてはならない（MUST）。Shift+clickは連続選択で開いたままにする。最近使ったからはコピー、お気に入り同士は並べ替え、バー外への所定ドロップは削除とする。キーボードにも削除経路を持つ。

#### Scenario: 満杯へ追加

- **WHEN** 上限まで埋まったお気に入りへ新規追加する
- **THEN** 元の配列を保持して追加不能を呼び出し側へ返す

#### Scenario: タッチでスクロール

- **WHEN** 縦スクロールするクイックパレットを操作する
- **THEN** 既定でドラッグを始めずスクロールを守る

<a id="emoji-04"></a>

### Requirement: EMOJI-04 Bluemojiの公開境界

カスタム絵文字は本人PDSへ保存し、Nagiが作ったものは同じrkeyのサイドカーで識別しなければならない（MUST）。名前をrkeyに固定せず十分にランダムなkeyを使い、同名旧レコードと衝突させない。ラスタは長辺128pxを基準に小さく保つ。

#### Scenario: 同名の再作成

- **WHEN** 古い同名レコードがPDSに残る
- **THEN** 名前由来keyの衝突で作成不能にしない

<a id="emoji-05"></a>

### Requirement: EMOJI-05 生成画面と登録の冪等性

生成UIは進行中依頼と最新結果の1枚の画面を持ち、旧設計の常時複数候補UIと混同してはならない（MUST）。生成idごとに入力フォームとrkeyを維持し、再取得で編集中の名前を消さず、登録の再試行で重複を作らない。data URL候補はCSPに依存するfetch(data:)を避けて復元する。

#### Scenario: 応答喪失後の再登録

- **WHEN** PDS書き込み応答だけを失って押し直す
- **THEN** 同じrkeyで書き別の絵文字を増やさない

#### Scenario: 一覧の更新

- **WHEN** ユーザーが候補名を編集中にpollする
- **THEN** フォームをbot提案の初期値で上書きしない

<a id="tag-01"></a>

### Requirement: TAG-01 正規形と表示用文字列

検索・ミュート・保存のタグは先頭#または＃を外した小文字へ正規化しなければならない（MUST）。プロフィール等の表示用原文ケースとは区別する。空・長過ぎ・空白入りを拒否し、重複は先着、満杯は元配列を保持する。最近タグは成功投稿の出現順で積む。

#### Scenario: 全角記号と大文字

- **WHEN** ＃Nagiを保存する
- **THEN** 正規形nagiを使うが表示原文の大文字を強制変更しない

<a id="tag-02"></a>

### Requirement: TAG-02 タグパレットと文脈メニュー

パレットはお気に入りと最近を並べ、挿入時は#tagと後続空白を本文へ入れて入力に戻さなければならない（MUST）。本文タグの右クリック・長押しは画面1つのメニューでお気に入り・タブ・ミュート・一覧への操作を行う。長押し後のclickを抑制し誤遷移させない。

#### Scenario: iOS長押し

- **WHEN** contextmenuを出さないブラウザでタグを長押しする
- **THEN** 独自タイマーでメニューを開く

#### Scenario: パレット挿入

- **WHEN** タグを選ぶ
- **THEN** 本文へ挿入して入力欄へフォーカスを戻す
