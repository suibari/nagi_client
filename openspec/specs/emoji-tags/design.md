# 絵文字・タグ・生成UI：設計判断

## この文書の役割

[spec.md](spec.md) が定める振る舞いについて、課題・採用判断・理由と制約を説明する。実装の行番号に依存せず、判断が変わるときに更新する。原文にない過去の議論や、採用されなかった案を推測で補わない。

## 設計判断

### D1: 内蔵検索の言語・文字数制限を補う

**課題**：emoji-picker-elementの内蔵検索は2文字未満を捨て、日本語データには英語キーワードが無い。

**採用判断**：ja/enを絵文字文字列で結合した索引を使い、NFKC・大小文字・かなを正規化して検索する。

**理由と制約**：完全一致等の質を優先し、カスタム絵文字を先に表示する。登録直後の本人定義はPDSキャッシュで補い、取り込み待ちでも検索から失わない。

### D2: 追加不能を無言の成功にしない

**課題**：満杯の配列へ足してsliceすると、足した本人の絵文字だけが切れ、何も起きなかった理由が分からない。

**採用判断**：既存・満杯時は元配列を保ち、追加不能を呼び出し側が判定できるようにする。

**理由と制約**：最近からお気に入りはコピー、既存お気に入りは並べ替えとして扱う。タッチのスクロールとドラッグを混同せず、キーボードの削除経路も残す。

### D3: 生成結果の再取得と登録を冪等にする

**課題**：pollで一覧を取り直すたび入力を初期化したり、応答喪失後に別keyで登録したりすると内容消失や重複が起きる。

**採用判断**：生成idごとに入力フォームとrkeyを保持し、進行中と最新結果を1画面へまとめる。

**理由と制約**：旧設計案の複数候補・履歴を現行保証にしない。候補のdata URLはCSPに掛かるfetchを避け復元し、再登録でも同じ公開レコードを使う。

### D4: 検索用の正規形と表示原文を区別する

**課題**：タグを場所ごとに別の方法で正規化すると検索・ミュート・お気に入りの対象が一致しない。

**採用判断**：保存や照合は#を外した小文字へ揃え、プロフィール等で見せる元の表記は保つ。

**理由と制約**：履歴は成功した投稿だけを記録する。長押しメニュー後のclickを抑え、メニューを開いた意図とページ遷移を混ぜない。

- [導入時コメント原文](../../reference/comment-snapshot/emoji-tags.md)は、基準コミット `24aad5eebea23501b9f7f0b9dfcbde2aa6f6bfdf` の固定資料である。原文内の行番号はそのコミットだけを指す。
- [機械可読台帳](../../comment-catalog.json)に元ファイル・行範囲・原文・SHA-256を保持する。コメント削減後も履歴として残し、現在のコードに合わせて書き換えない。
- [既知の不整合](../../known-gaps.md)に現在の要件と旧説明の違いを記録する。改善が実装済みとは扱わない。
