## 調査対象

- Git追跡対象のソース・設定 **670ファイル** を列挙。コメントを持つ **462ファイル** から **3227ブロック** を採録。連続する `//` 行は1ブロックにまとめる。
- 本番コード、Vercel Functions、Service Worker、静的初期化JS、Svelteのscript・template・style、CSS、型宣言、ユニットテスト、E2Eテスト、開発モック、JSON内のコメント、YAML等の設定注記を含む。
- TypeScriptは構文木のトークン境界からコメント位置を抽出し、文字列・正規表現中の `//` をコメントに誤認しない。Svelteはcompilerのscriptコメントとtemplate AST、style内コメントを採録する。CSSは引用文字列を飛ばす。
- 依存ライブラリ、ビルド生成物、バイナリアセット、lockfile、秘密の `.env.local`、Git内部データは対象外。`.prettierrc` はコメントのないJSON設定であることを別途確認し、`LICENSE` はライセンス原文のまま保持する。既存Markdown文書は背景資料として入口から参照し、コードコメント台帳へは重複採録しない。
- コメントの無いファイルも台帳にファイルハッシュと空配列を記録する。抜けとコメント無しを区別する。`--check-current`では未追跡の新規ソースも探索し、列挙の差分として検出する。

## 再確認

アプリ依存が利用可能なリポジトリルートで実行する。

```sh
node openspec/tools/comment-catalog.mjs --check
node openspec/tools/comment-catalog.mjs --check-current
npx --yes @fission-ai/openspec@1.17.0 validate --all --strict --no-interactive
```

検査は読み取り専用。`--check`（引数なしも同じ）は、台帳と採録コミットのソース・原文資料を比較し、全出典、固定リンク、現在の文書構成・ローカルリンクを確認する。採録コミットを含むGit履歴が必要になる。将来のアプリ変更で現行コードの行が移っても、固定した出典の検査は継続できる。

`--check-current` は上記に加え、現在のソース列挙・SHA-256・コメントが導入時と同じかを検査する。今回はコードを変更しない文書化のため、こちらも成功を確認した。将来のコード変更後には意図的に失敗するが、そのために履歴台帳を書き換えない。
